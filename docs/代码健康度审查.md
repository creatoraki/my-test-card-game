## 三、问题清单

### P0：影响交付物或正确性

#### 1. 演示页被打进生产包，且正式代码依赖演示目录
- 证据：[App.tsx](../src/App.tsx) 第 15 行静态 `import { TestScreen } from "@/ui/test/TestScreen"`；`src/ui/test` 共 98 个 TS 文件、约 2.78 万行（含 CSS），约占全部代码的 19%。
- 反向依赖：[emblemGeometry.ts](../src/ui/common/BuffIcon/emblemGeometry.ts) 从 `@/ui/test/opus/CultivationSigil/cultivationGeometry` 引入几何常量。删除或整理演示目录时，正式的培育徽记会一起坏掉。
- 建议：
  - 把 `cultivationGeometry` 移到 `ui/common/BuffIcon/`，演示页反过来引用它；
  - `TestScreen` 改为 `React.lazy(() => import(...))`，并用 `import.meta.env.DEV` 包裹，生产包不再打入演示代码。

#### 2. 开发环境默认“敌人 1 血”
- 证据：`.env.development` 中写着 `BattleTest=true`；[battleSetup.ts](../src/engine/battleSetup.ts) 第 19 行直接读取 `import.meta.env.BattleTest`，第 92 行把敌人 `maxHp` 设为 1。
- 影响：`pnpm dev` 下所有战斗的平衡体验都会失真；纯引擎层也因此依赖 Vite 的环境变量，测试环境要额外兜底。
- 建议：默认改为 `false`，需要时再在本地 `.env.development.local` 中打开；由 store 层把开关作为建局参数传给 `createBattleState`，引擎不再直接读取环境变量。

## 四、做得好的地方
- **纯逻辑层与表现层分离**：engine / explore / items 不依赖 React，由 store 层先 `structuredClone` 再调用纯函数，这一约定贯彻得一致。
- **可复现随机**：战斗、探索和掉落共用 `engine/rng` 的种子链，注释里明确禁止使用 `Math.random`。
- **唯一真相点**：规则常量集中在 `engine/rules.ts` 与 `explore/rules.ts`，粒子计价集中在 `explore/energyCost.ts`，美术统一登记在 `ui/art/*`，数据层不直接接触素材。
- **样式隔离**：组件样式全部使用 CSS Modules，全局层只有 `tokens.css` 与 `base.css`。
- **注释质量高**：关键文件头部都写了“为什么”和“易踩坑”，新人上手成本低。
