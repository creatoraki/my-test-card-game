# 交互物现状说明

> 2026-10-10 整理自当前代码，只描述**已经实现**的内容。
> 交互物在代码里叫 curio（物件），种类代号是 `CurioKind`。
> 全部物件素材只用 `src/assets/explore-corridor/通用交互物/`，事件名称与文案按素材外观编写，见各分类表的「素材」列。

---

## 一、设计原则

1. **没有等级**：所有交互物只有一套数值，不按地图、难度、房间深度放大或缩小。
2. **一种物件对应多类产出**：搜刮类和恢复类每种物件有 4 个候选品类，**交互时**不重复地随机抽 2 类、每类给 1 件，结算后玩家才知道拿到了什么。
3. **喂养 = 多抽一类且必定成功**：背包里有机械小生物爱吃的食物时，会多出一个喂养选项，改为 4 选 3，而且不会失败。
4. **失败率隐藏**：失败只体现在结算文案里；执行者职业、背包物品可以降低失败率、追加奖励，或把失败转成好结果。

---

## 三、功能模块设计

### 1. 分层与文件

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 定义 | `src/data/curios/defs/*.ts` | 按功能分文件：搜刮 `loot`、恢复 `supply`、熔合与神龛 `craft`、装备调校 `growth`、NPC `service`、陷阱 `trap`、方舟 `ecoArk`、新手 `tutorial` |
| 注册与投放权重 | `src/data/curios/index.ts` | `CORRIDOR_CURIOS` 总表、`RANDOM_CURIO_WEIGHTS`、`HEAL_CURIO_KINDS`、`TRAP_CURIO_KINDS` |
| 规则 | `src/data/curios/rules/` | 奖励池 `rewardPools`、失败率上限与警报档位 `curioRules`、定义辅助函数 `helpers`（`roll` / `poolItem` / `fail` / `byJob` / `withItem` / `feedDecision`） |
| 投放 | `src/explore/dungeon/curioPlan.ts` | 每间房放哪些物件 |
| 结算 | `src/explore/curio/` | 选择 → 扣费 → 失败判定 → 展开抽取 → 执行效果 → 收尾 |
| 粒子计价 | `src/explore/resources/energyCost.ts` | 按分类收交互粒子，唯一计价口 |
| 界面 | `src/ui/explore/ExploreScreen/parts/CurioPanel.tsx` 等 | 事件档案面板；NPC 各有专用面板 |
| 插图主题 | `src/ui/explore/ExploreScreen/parts/curioTheme.ts` | 物件 → 事件档案主题 |
| 场景素材 | `src/ui/art/corridor/commonPropAssets.ts`、`commonPropArt.ts`、`commonPropTuning.ts` | 素材登记与尺寸档 / 物件 → 素材分配 / 预览页调好的游戏内倍率与上下偏移 |

### 2. 一个物件的数据结构（`CurioDef`）

```
CurioDef
├─ name / description / verb      事件名称、描述、交互按钮动词
├─ role                           loot / heal / service / trap，决定粒子价格和历史记录分类
├─ forced / persistent            陷阱强制触发 / NPC 常驻
└─ decisions[]                    玩家可选的选项
    ├─ effects[]                  效果列表（见下）
    ├─ failure                    隐性失败：概率、失败文案、惩罚、门槛
    ├─ foodCost                   明码收食品
    ├─ feed                       喂机械小生物（背包有对应食物才显示）
    └─ select                     需要玩家挑物品（熔合装备、升级遗物）
```

**效果**（`CurioEffect`）是物件能做的全部事情，结算在 `explore/curio/effects.ts`：

| 效果 | 作用 |
| --- | --- |
| `ROLL_EFFECTS` | 从候选效果里不重复抽 `pick` 条执行（「4 选 2」就是它） |
| `GAIN_POOL_ITEM` | 从奖励池按权重抽物品，放进待拾取框 |
| `DAMAGE_MEMBER_PERCENT` | 按百分比扣血 |
| `ADJUST_POLLUTION` | 增减污染 |
| `REVEAL_MAP` | 揭示地图（可含战斗、陷阱位置） |
| `FUSE_EQUIPMENT` / `UPGRADE_RELIC` | 熔合装备 / 升级遗物 |
| `FORGE_DRAW_TAINTED` / `REPLACE_CARD_COMMON` | 卡牌三选一 / 换成普通卡 |
| `TUNE_EQUIPMENT` | 装备重铸羁绊或重置完美度 |
| `GRANT_DISPOSABLE_RELIC` | 一次性遗物 |
| `CONSUME_ITEM` | 扣背包物品 |
| `ALARM_BATTLE` | 失败引来守卫战（固定 t1 档） |
| 其余探索通用效果 | 治疗、补粒子、给装备、给遗物、给经验、打开信使等 |

奖励池（`rules/rewardPools.ts`）：材料、材料或钱币、钱币、高价值钱币、水晶、基础食品、食品、高级食品、应急道具、模组；池内按权重抽，难度可剔除个别物品（普通难度不出金币）。

### 3. 投放

1. **起点房**：只放临时祝福匣。
2. **其余房间**：每间 1～2 个物件。
   - 货商、锻造师先占名额（锻造师每张地图固定一位）；
   - 陷阱房固定放 1 个陷阱；非陷阱房有 20% 概率放 1 个恢复物件；
   - 剩余名额按 `RANDOM_CURIO_WEIGHTS` 加权、房内不重复抽取：战术背包 30、研究员工作站 22、密码寄存柜 10、合成实验台 3、织梦机 2、神龛 2、环锁密匣 2、记忆坛 1。
3. **信使**：每房 10% 概率额外放一位，整图至少一位。
4. **地图覆写**：地图可在 `curioPool` 里加权重、替换恢复池和陷阱池（生态方舟就是这样接入独有物件的）。

### 4. 交互流程

```
玩家走近物件 → 打开事件档案 → 选执行者 + 选项
   │
   ├─ 普通选项 chooseCurioDecision
   └─ 选物选项 selectForCurio（配方必须完全匹配，否则什么都不扣）
   ↓
扣费：食品 foodCost → 喂养食物 → 交互粒子（陷阱免费，免费次数优先）
   ↓
失败判定 resolveFailure（概率完全隐藏）
   最终失败率 = 选项基础值 + 门槛修正 + 遗物修正，上限 95%
   门槛 = 执行者职业 或 背包指定物品（物品生效即消耗）
   门槛三种用法：降低失败率 / 成功追加奖励 / 把失败转成正面结果
   ↓
按结果取效果 → expandRolls 掷完全部候选抽取 → 逐条执行
   单人效果（治疗、体力极限）直接作用于执行者
   ↓
收尾 finishInteraction：物件标记已用、写回房间、记历史和日志
   → 房间物件清空时触发「清房」遗物 → 进入结算阶段
   ↓
结算界面：待拾取框、卡牌三选一、装备调校、守卫战等后续动作依次处理
```

### 5. 新增一个交互物要改哪里

1. `explore/corridor/types.ts` 的 `CurioKind` 加代号；
2. 在对应功能的 `data/curios/defs/*.ts` 写 `CurioDef`；有多类产出时用 `roll(2, [...4 个候选])`；
3. 需要随机投放就在 `RANDOM_CURIO_WEIGHTS` 或地图 `curioPool` 加权重；
4. `curioTheme.ts` 指定事件档案主题；
5. `commonPropArt.ts` 从 `通用交互物/` 分配素材（新素材先在 `commonPropAssets.ts` 登记），到缩放预览页调好倍率和偏移后录入 `commonPropTuning.ts`；
6. 现有效果不够用时，才在 `CurioEffect` 加新类型并在 `effects.ts` 实现。
