 # 《霓虹都市》· 装备可加成属性清单

 > **状态**：用于后续装备数值模板设计的属性池整理。
 >
 > 本文整理角色养成设计中已经存在、且适合由装备提供的加成入口，并规定装备模型、属性类型与稀有度数值梯度；具体掉落来源和羁绊效果另行设计。

 ---

 ## 一、设计结论

 角色没有等级、属性点和可重复升级的基础面板。装备设计时，能够直接写入角色面板的属性，以 `StatBlock` 的 17 项属性为完整候选池：

 - 武器主要承担输出与命中、暴击相关属性。
 - 防具主要承担生命、防御与承伤相关属性。
 - 饰品主要承担治疗、节奏、探索和小队资源相关属性。
 - 规则词条可以改变战斗或探索规则，但不应伪装成新的基础属性。

 装备提供的是**局外常驻修正**。进入战斗时，先将角色基础值与装备固定值、装备百分比修正合并；卡牌、状态、关键词模组和场景再提供本场战斗的临时修正。

 ```text
 最终属性 = (角色基础值 + 装备固定值) × (1 + 装备百分比修正)
					+ 战斗内固定修正
					× (1 + 战斗内百分比修正)
 ```

 同名百分比效果默认相加。具体数值要按本文的装备类型和属性预算规则设计；同一装备模型的稀有度只改变既有属性的数值。

 ---

 ## 二、装备模型与两类属性

 ### 2.1 同一模型只有一种物品

 - 同一 `familyId` 代表同一个装备模型。模型只有一种物品名称，普通、精良、稀有、史诗、传说只是它的五个稀有度数值档位。
 - 同一模型在所有稀有度下必须保持相同的装备槽、属性目标、属性正负方向和属性结构。
 - 稀有度只能改变已有属性的数值，不能新增属性、移除负面属性、改变属性方向或追加仅高稀有度拥有的规则词条。
 - 如果属性结构不同，就应该设计为新的装备模型和新的 `familyId`，不能用同一模型的不同稀有度表达。
 - 实现层可以为了掉落权重拆成多条 `ItemDef`，但这些定义必须共享 `familyId`，玩家界面显示同一个装备名称和不同稀有度。

 ### 2.2 两类装备

 | 装备类型 | 属性规则 | 使用体验 |
 | --- | --- | --- |
 | 固定加成型 | 提高一组职责相近的正面属性，不降低其他正面属性。 | 稳定补强角色面板，收益容易预期。 |
 | 极端加成型 | 集中提高少数属性，同时降低其他原本具有正面价值的属性。 | 牺牲整体收益，换取明确的战术倾向。 |

 极端加成型的降低项必须是真实的正面属性，例如先手、命中率、防御力或最大生命值。代价不能使用无关字段，也不能在高稀有度时消失。

 ### 2.3 总属性预算

 不同属性的原始数值不能直接相加。先按统一的属性点折算表将固定值、百分点和倍率百分点换算为属性预算，再计算装备的净属性：

 $$
 	ext{净属性预算} =
 \sum_i w_i \cdot \max(v_i, 0)
 -
 \sum_i w_i \cdot \max(-v_i, 0)
 $$

 其中 $v_i$ 是统一单位后的属性修正，$w_i$ 是该属性的平衡权重。属性点折算表由数值平衡维护，不能把 `+10 最大生命值` 与 `+10% 暴击率` 的原始数字直接相加。

 在相同槽位、相同稀有度和相同预算级别下，必须满足：

 $$
 	ext{净属性预算}_{\text{极端加成型}}
 <
 	ext{净属性预算}_{\text{固定加成型}}
 $$

 极端加成型可以让目标属性高于固定加成型，但扣除负面属性后，整体净属性必须更低。它的价值是改变构筑方向，而不是成为固定加成型的全面上位替代。

 例如，**十字剑**属于极端加成型武器：增加最大生命值和攻击力，降低先手。所有稀有度的十字剑都保留这三个属性方向，只改变三个数值的大小。

 ## 三、可直接加成的角色属性

 以下 17 项均属于角色面板属性，可以成为装备的直接加成目标。属性名以 `src/engine/types.ts` 的 `StatBlock` 为准。

 | 属性 | 主要用途 | 属性表现 | 适合的装备方向 |
 | --- | --- | --- | --- |
 | 最大生命值 `maxHp` | 提高角色可承受的总伤害。 | 固定值为主。 | 防具 |
 | 攻击力 `attack` | 提高攻击卡和技能的倍率伤害。 | 固定值为主。 | 武器 |
 | 治愈力 `healPower` | 提高角色作为施放者造成的基础治疗。 | 固定值为主。 | 饰品 |
 | 防御力 `defense` | 降低受到的非固定伤害。 | 固定值为主；减伤比例为 `防御力 / (防御力 + 30)`。 | 防具 |
 | 命中率 `hitRate` | 提高可闪避攻击、控制和异常的命中概率。 | 百分点，例如 `+8` 表示 `+8%`。 | 武器 |
 | 闪避率 `dodgeRate` | 降低可闪避攻击的命中概率。 | 百分点；最终值不超过 70%。 | 防具或饰品 |
 | 暴击率 `critRate` | 提高可暴击伤害触发暴击的概率。 | 百分点；最终值不超过 70%。 | 武器 |
 | 爆伤 `critDamage` | 提高暴击后的伤害倍率。 | 百分比值；`150` 表示 `150%` 倍率。 | 武器 |
 | 精准 `precision` | 对抗目标闪避，优先抵消目标闪避率。 | 百分点，不受 70% 概率上限限制。 | 饰品 |
 | 先手 `initiative` | 推迟敌方技能的实际行动时刻。 | 固定值为主。 | 饰品 |
 | 格挡率 `blockRate` | 受到可格挡攻击时，有概率使本次伤害减半。 | 百分点；最终值不超过 70%。 | 防具 |
 | 治愈强度 `healBoost` | 按比例放大有效治疗。 | 百分比修正；不影响百分比恢复和直接满血效果。 | 饰品 |
 | 护盾强度 `shieldBoost` | 按比例放大卡牌、技能和被动产生的护盾。 | 百分比修正；不影响写明固定值的开局护盾。 | 防具 |
 | 异常抗性 `ailmentResist` | 抵抗负面状态的施加、层数或持续时间。 | 百分点；最终值不超过 70%。具体抵抗项由异常定义。 | 防具 |
 | 负重适应 `burdenAdapt` | 抵消当前远征因背包占格产生的命中、闪避和暴击惩罚。 | 百分点；小队合计后不超过 100%。 | 饰品 |
 | 手牌上限 `handLimit` | 提高全队共享手牌区的最大容量。 | 固定值；按上阵角色装备贡献累加。 | 饰品 |
 | 抽牌数 `drawCount` | 提高全队基础抽牌数。 | 固定值；当前实现以全队固定基准为底再叠加。 | 饰品 |

 ### 3.1 加成口径

 | 加成类型 | 适用属性 | 设计时的写法 |
 | --- | --- | --- |
 | 固定值加成 | 最大生命值、攻击力、治愈力、防御力、先手、手牌上限、抽牌数等。 | `攻击力 +3`、`最大生命值 +8`。 |
 | 概率百分点加成 | 命中率、闪避率、暴击率、精准、格挡率、异常抗性等。 | `暴击率 +5%`，内部记录为 `+5`，不是乘以 `1.05`。 |
 | 倍率百分点加成 | 爆伤、治愈强度、护盾强度。 | `爆伤 +10%`、`护盾强度 +8%`。 |
 | 远征百分比加成 | 负重适应。 | `负重适应 +15%`，按百分点抵消负重惩罚。 |

 `maxHp` 是最大生命值，不等同于当前生命值。装备提高最大生命值时，不应默认视为治疗；装备更换时当前生命值如何处理，留到装备穿脱规则中单独确定。

 ## 四、装备槽位的推荐归属

 下表是“优先放置位置”，不是绝对禁止跨槽位。跨槽位时应降低数值或附加明确代价，避免单一装备同时覆盖多个成长方向。

 | 装备槽 | 首要属性 | 可少量承担的属性 | 不建议承担 |
 | --- | --- | --- | --- |
 | 武器 | 攻击力、命中率、暴击率、爆伤。 | 精准、与输出相关的规则词条。 | 高额最大生命值、防御力、格挡率、手牌与抽牌。 |
 | 防具 | 最大生命值、防御力、格挡率、异常抗性、护盾强度。 | 闪避率、与承伤相关的规则词条。 | 高额攻击力、暴击率、爆伤。 |
 | 普通饰品 | `StatBlock` 中的全部属性均可出现，允许攻击与防御属性混合。 | 规则词条与队伍资源效果。 | 在同一件饰品上同时堆叠过高的攻击和防御收益。 |
 | 羁绊饰品 | 固定羁绊 +1、随机副羁绊 +1。 | 改变构筑的专属规则效果。 | 攻击力、最大生命值、命中率等常规基础属性。 |

 推荐的槽位分工来自角色养成设计中的职责边界：武器偏输出，防具偏生存，饰品偏自由组合与队伍构筑。普通饰品可以从完整属性池中补足角色短板，但同一件饰品不应同时堆叠过高的攻击和防御收益。羁绊饰品仍不提供常规面板属性，其价值来自改变构筑可能性。

 ---

 ## 五、属性的结算与限制

 ### 5.1 战斗属性

 - 攻击力只影响使用攻击力倍率的伤害；明确写为固定伤害的效果不使用攻击力。
 - 治愈力属于施放者属性，治愈强度属于治疗结果的比例修正；两者不是同义属性。
 - 防御力属于承受者属性，固定伤害不受防御力影响。
 - 命中判定建议统一使用：

	 $$
	 P_{hit} = \operatorname{clamp}(P_{base} + \text{命中率} + \text{精准} - \text{目标闪避率},\ 5\%,\ 100\%)
	 $$

 - 暴击率、闪避率、格挡率和异常抗性的最终值采用 70% 硬上限。
 - 命中率和精准不设属性硬上限，但最终命中概率仍限制在 5% 至 100%。
 - 爆伤不设通用硬上限，但普通装备不宜稳定提供过高爆伤；高爆伤更适合短时战斗效果或高代价装备。
 - 格挡率只影响可格挡攻击；格挡成功后的减伤比例由规则统一设定，不由装备自由改变。
 - 护盾强度只放大符合定义的动态护盾，不影响写明固定值的开局护盾。
 - 异常抗性不默认同时降低异常命中、层数和持续时间；每种异常必须明确采用哪一种抵抗方式。

 ### 5.2 探索与小队属性

 - 负重适应只抵消负重带来的固定惩罚，不能把背包占格转化为额外的命中、闪避或暴击收益。
 - 负重适应按上阵角色和全队效果合计，未上阵角色的装备不贡献该属性。
 - 手牌上限和抽牌数是小队属性，按上阵角色的装备贡献合计，再叠加全队规则效果。
 - 抽牌数当前不改变固定的开局抽牌与每回合基础抽牌规则，只作为装备和成长的额外加成入口。
 - 装备不增加背包容量，也不减少物品占格；这两者不能与负重适应混用。

 ### 5.3 属性修改结构

 装备属性建议统一使用 `StatModifier`：

 ```ts
 {
	 flat: { attack: 3, maxHp: 8 },
	 pct: { critDamage: 10 }
 }
 ```

 - `flat` 表示固定值加成。
 - `pct` 表示百分比修正，按百分点记录；同名百分比默认相加。
 - 概率属性的 `+5` 表示增加 5 个百分点，不表示乘算 5%。
 - 装备的局外修正与战斗内修正共用属性结构，但生命周期不同；装备不会因为战斗结束而消失。

 ## 六、不作为直接面板属性的装备效果

 以下内容可以由装备规则词条、羁绊或专属效果实现，但不应新增为角色的常驻基础属性：

 | 内容 | 推荐实现方式 | 原因 |
 | --- | --- | --- |
 | 法力水晶、开局资源 | 全队规则词条或开局效果。 | 当前 `StatBlock` 没有资源属性；资源不是角色面板。 |
 | 固定开局护盾 | 装备规则词条或开局效果。 | 护盾强度只放大动态护盾，不能替代固定护盾数值。 |
 | 伤害类型、伤害倍率、额外攻击段数 | 输出规则词条、卡牌或技能效果。 | 攻击力只负责倍率基数，不能让面板承载完整技能规则。 |
 | 格挡减伤比例 | 统一战斗规则或高稀有度专属词条。 | 普通格挡率与格挡成功后的减伤是两件事。 |
 | 状态施加、状态层数与持续时间 | 卡牌、状态或专属装备规则词条。 | 异常抗性只负责抵抗，不直接生成异常。 |
 | 羁绊计数与羁绊激活效果 | 装备羁绊词条和全队羁绊规则。 | 羁绊是队伍构筑层，不是角色基础属性。 |
 | 卡组等级 | 卡组锻造消耗经验。 | 不由装备提高，且只影响新卡稀有度获取权重。 |
 | 最小卡组下限 | 卡组锻造消耗经验。 | 不由装备降低，避免装备替代卡组构筑。 |
 | 稀有度限携 | 卡组硬规则。 | 不能被卡组等级、装备或模组提高。 |
 | 背包容量、物品占格 | 背包与物品规则。 | 负重适应只能抵抗惩罚。 |
 | 当前生命值、即时治疗、即时护盾 | 消耗品、卡牌或装备触发效果。 | 不应与最大生命、治愈力、护盾强度混为同一属性。 |

 如果未来某个装备模型需要规则词条，该词条必须属于模型固定结构，并在所有稀有度保持一致；不能只在史诗或传说版本中新增规则效果。规则词条也应写成明确文本，例如“战斗开始时获得 4 点护盾”，而不是偷偷扩展 `StatBlock`。

 ## 七、后续设计装备时的检查清单

 每设计一件装备，先确认以下内容：

 1. 它属于固定加成型还是极端加成型？
 2. 它是否使用了同一装备模型固定的属性目标和正负方向？高稀有度是否只改变已有数值？
 3. 它提供的是 17 项面板属性中的哪一项，还是明确的规则词条？
 4. 该属性是否符合武器、防具或饰品的主要职责？
 5. 属性是固定值、百分点，还是倍率百分点？文本是否能让玩家区分三者？
 6. 按统一属性点折算后，极端加成型的净属性预算是否低于同槽位、同稀有度的固定加成型基准？
 7. 它是否触碰了 70% 概率上限、100% 负重适应上限或 5% 至 100% 命中概率边界？
 8. 它是否误把卡组成长、羁绊、背包容量或资源规则写成角色面板属性？
 9. 它的效果在穿戴期间持续，还是只在战斗开始、受击、出牌等时机触发？生命周期是否写清楚？

 ## 八、与现有装备总规则的关系

 - 本文负责回答“装备可以加成哪些角色属性”。
 - [物品设计总概念](物品设计总概念.md)负责装备槽、稀有度、羁绊饰品和重铸规则。
 - 正式装备名称、属性模板、统一属性点折算表、数值梯度和获取渠道应在本文后续继续补充。
 - 当本文与角色养成设计发生冲突时，以角色养成设计中的 `StatBlock`、结算顺序和装备职责边界为准，并同步修正文档。
