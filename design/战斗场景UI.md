# 战斗场景 UI 设计

## 一、设计范围

本次重新设计只调整战斗页面的 UI 布局、信息层级和交互展示，不改变战斗规则与角色立绘表现。

### 保留内容

- 角色立绘及当前队伍卡的整体表现。
- 手牌卡牌的主要视觉表现、横向排列和出牌动画。
- 战场中央的敌人立绘、受击表现、行动意图和镜头演出。

### 重新设计内容

- 战斗页面的 HUD 位置和分区。
- 费用、回合、时刻、挑战、羁绊、牌堆和卡牌详情的展示方式。
- 换牌、丢弃、查看牌堆和结束回合等战斗操作入口。
- 悬浮、选中、目标选择、不可用和动画锁定等交互状态。

### 明确不加入

- 战斗记录区不加入本次战斗 UI。
- 不把战斗日志、伤害历史或事件流水展示在页面上。

## 二、整体信息架构

战斗页面分成五个层级：

1. **顶部战斗信息栏**：回合、时刻和系统入口。
2. **左右辅助信息栏**：左侧挑战事件，右侧队伍羁绊。
3. **中央战场**：敌人、行动意图、目标选择和战斗演出。
4. **底部操作区**：队伍角色、牌堆、手牌、费用、换牌/丢弃和结束回合。
5. **悬浮详情层**：卡牌、羁绊、挑战和牌堆的详细说明。

布局原则：

- 中央区域只负责战场和敌人，不放大块信息面板，保证角色立绘和敌人行动清楚。
- 低频查看的信息使用图标常驻、悬浮展开，避免所有说明同时铺满画面。
- 会影响当前决策的信息常驻显示，例如回合、时刻、费用、挑战和羁绊激活状态。
- 所有面板都应保持稳定尺寸，悬浮详情出现时不能推动战场、手牌或角色立绘发生位移。
- 页面优先适配固定的 1920×1080 战斗画布，所有位置使用设计画布坐标。

## 三、顶部战斗信息栏

### 1. 回合进度

顶部固定显示：

- 当前回合数，例如 `回合 02`。
- 远征总回合数，例如 ` / 06`。
- 当前回合进度条或短刻度带。

回合数必须独立于时刻显示，不能只依靠时刻标尺中的小字表达。

### 2. 时刻信息

显示当前时刻和接下来几格时刻：

- 当前时刻使用高亮色。
- 后续时刻使用较弱的刻度显示。
- 如果未来允许公开敌人行动预览，可在对应刻度下显示敌人行动标记。
- 当前时刻和回合数都属于常驻信息，不随卡牌详情面板隐藏。

### 3. 系统入口

右上角保留一个小型设置按钮，后续可打开：

- 音量和动态效果设置。
- 快捷键说明。
- 返回主菜单或退出战斗的确认入口。

退出战斗目前不是战斗引擎已有操作。如果规则暂不支持撤离，设置面板只提供显示和音频选项，不显示“撤离”按钮。

## 四、费用与出牌预览区

费用区是战斗中的核心决策反馈，放在底部操作区靠近手牌的位置，同时在顶部保留简短读数或状态灯。

### 常驻信息

- 当前费用：`02 / 03`。
- 当前回合费用是否已经用尽。
- 费用不足时显示明确的不可用状态。
- 每回合费用刷新时播放短暂的数值变化反馈。

### 悬停和选中卡牌时

当鼠标悬停或选中一张卡牌时，费用区显示：

```text
当前费用        03 / 03
使用「卡牌名称」  - 02
使用后剩余      01 / 03
```

规则：

- 未悬停或未选中卡牌时，只显示当前费用。
- 悬停卡牌时显示该卡的费用预览，但不改变选中状态。
- 选中卡牌进入目标选择状态后，费用预览保持显示。
- 卡牌费用超过当前费用时，使用后数值显示为不可用状态，并同步禁用出牌。
- 换牌和丢弃模式下不显示“使用后剩余费用”，避免误导玩家。

费用预览只属于 UI 计算：`当前费用 - 卡牌费用`，不改变引擎资源，实际扣费仍由战斗引擎处理。

## 五、挑战事件区

### 常驻形态

挑战事件区放在战场左侧，使用一个标题和若干图标组成的紧凑区域：

- 显示当前战斗生效的挑战图标。
- 多个挑战并列显示，最多时自动换成纵向排列。
- 激活中的挑战使用明亮描边。
- 已经生效但没有额外奖励的条件，也必须显示，不能只显示有收益的挑战。
- 图标下方可显示简短的奖励或风险标记。

### 悬浮详情

鼠标悬浮或键盘聚焦挑战图标时，显示详情浮层：

- 挑战名称。
- 挑战类型或来源。
- 对本场战斗的实际影响。
- 对掉落、经验或其他收益的实际影响。
- 如果效果被当前引擎降级，显示真实生效的版本，不显示未实现的描述。

挑战详情浮层不能遮挡当前敌人的意图和血条；靠近边缘时自动翻转到可见方向。

### 数据口径

当前挑战主要来自探索阶段的战斗签 `SlotSymbol`。进入战斗后应将已选挑战的标题、图标、描述和实际改造保存为本场战斗快照，再交给战斗 UI 展示。战斗页面不应依赖探索页面仍然挂载才能显示挑战。

## 六、队伍羁绊区

羁绊区放在战场右侧，采用类似自走棋羁绊栏的紧凑图标组。

### 常驻显示

无论是否达到最低激活门槛，只要羁绊存在就显示：

- 羁绊图标。
- 羁绊名称。
- 当前点数，例如 `2`。
- 当前激活等级，例如 `Lv.1`，未激活时显示 `未激活`。
- 下一档门槛，例如 `2 / 3`。
- 当前激活状态、未激活状态和已满级状态使用不同的颜色和描边。

未达到最低门槛的羁绊不能隐藏，否则玩家无法判断自己距离激活还差多少。

### 羁绊图标状态

- **未激活**：低饱和度图标，显示当前点数和下一档门槛。
- **已激活**：使用羁绊主题色和发光描边，显示当前最高等级。
- **即将升级**：下一档只差 1 点时增加轻微提示，不使用持续闪烁。
- **已满级**：显示满级标记，不再显示不存在的下一档。

### 悬浮详情

悬浮羁绊图标时显示完整等级列表：

```text
力量  ·  当前 6 点  ·  Lv.2

3 点    全队攻击力 +3       已激活
6 点    全队攻击力 +6       当前等级
9 点    全队攻击力 +10      未激活
```

详情必须包含：

- 羁绊名称、图标和主题色。
- 羁绊主题描述。
- 当前点数。
- 所有等级的触发门槛和具体效果。
- 当前激活等级和距离下一档还差多少点。

羁绊数据沿用 `BOND_DEFS`、`activeBonds` 和 `nextTier` 的现有口径。战斗中显示的是开战时的羁绊快照，与实际作用到角色属性的羁绊保持一致。

## 七、底部牌桌操作区

底部区域是战斗操作的主要工作区，角色立绘和手牌保持当前满意的表现，周围只补充新的操作入口。

### 1. 抽牌堆按钮

显示：

- 抽牌堆图标。
- 当前剩余数量。
- 点击后打开抽牌堆查看面板。

查看面板只读，不允许改变牌堆顺序。抽牌堆为空时显示“将弃牌堆洗回”的规则提示，但不需要额外按钮。

### 2. 队伍角色区

保留现有角色立绘、血量、护盾、污染、状态和角色聚焦表现。

需要额外保证：

- 友军目标选择时，可选角色有明确高亮。
- 不可选或阵亡角色保持不可点击状态。
- 悬停手牌时，卡牌归属角色继续高亮。
- 角色区不能因为牌堆面板或卡牌详情展开而改变位置。

### 3. 手牌区

保留现有手牌视觉与排列方式，补充以下状态：

- 悬停卡牌显示卡牌详情和费用预览。
- 选中需要目标的卡牌后保持高亮，直到取消或完成出牌。
- 进入换牌模式时，所有可换卡牌显示统一提示。
- 进入丢弃模式时，所有可丢弃卡牌显示统一提示。
- 不可用卡牌明确区分“费用不足”“角色阵亡”“目标条件不满足”等原因。
- 手牌数量和手牌上限保持可见，例如 `05 / 10`。

### 4. 弃牌堆按钮

显示弃牌堆图标和数量。点击后打开当前弃牌列表：

- 显示卡牌名称、费用、归属和缩略图。
- 支持悬浮查看单卡详情。
- 不允许在查看面板中直接把卡牌移回手牌。
- 抽牌堆洗回弃牌堆时，按钮数量和提示同步更新。

### 5. 消耗堆按钮

显示消耗堆图标和数量。点击后打开本场已永久移除卡牌的列表：

- 与弃牌堆使用不同图标和颜色，避免玩家误以为它们会自动洗回。
- 空消耗堆也保留按钮位置，显示 `0`，保持布局稳定。
- 卡牌详情中标记“本场已消耗”。

### 6. 换牌按钮

- 每回合最多使用一次时，显示剩余次数或可用状态。
- 点击后进入换牌模式，再点击一张手牌完成换牌。
- 再次点击按钮可以取消换牌模式。
- 换牌模式中不允许误触结束回合或选择敌人目标。
- 换牌完成后退出模式，并清除已经消失卡牌的详情状态。

### 7. 丢弃按钮

- 点击后进入丢弃模式。
- 再点击一张手牌将其置入弃牌堆。
- 再次点击按钮可以取消丢弃模式。
- 丢弃模式下不能触发正常出牌和目标选择。
- 按钮应显示清晰的禁用状态，而不是从布局中消失。

### 8. 结束回合按钮

- 固定在底部操作区右侧。
- 正常玩家阶段可用，动画、目标选择、换牌和丢弃确认期间禁用。
- 点击后开始敌人行动演出，并锁定其他战斗操作。
- 按钮旁显示当前回合结束后会发生的关键规则提示，例如敌人冲刷行动。

## 八、卡牌详情区

卡牌详情区采用悬浮展开的固定面板，不占用中央战场的永久空间。

### 显示时机

- 鼠标悬停手牌时显示对应卡牌。
- 选中需要目标的卡牌后，即使鼠标离开手牌，详情仍保持显示。
- 点击空白区域取消选中时，详情回到待机状态。
- 换牌或丢弃完成后，不继续显示已经离开手牌的卡牌。

### 详情内容

- 卡牌插画或稳定尺寸的无图占位。
- 卡牌名称和归属角色。
- 费用。
- 当前费用和使用后剩余费用。
- 普通牌 / 速攻牌。
- 目标类型和实际作用范围。
- 稀有度、标签、强化状态和污染状态。
- 卡牌描述。
- 消耗、抽牌、护盾、状态等额外效果说明。

卡牌详情面板必须固定尺寸，切换不同卡牌时不能因为描述长度不同而让手牌整体跳动。详情面板可以根据鼠标位置选择左上、右上或手牌上方的安全位置，但不能盖住当前目标单位的关键血条和行动意图。

## 九、目标选择与出牌反馈

这是除卡牌详情之外，战斗操作最需要补充的一组反馈。

### 目标选择状态

选中需要目标的卡牌后：

- 卡牌保持明显的选中边框。
- 允许作为目标的敌人或友军显示高亮。
- 不符合目标类型的单位显示不可选状态。
- 鼠标悬停目标时显示即将作用的目标提示。
- 点击已选卡牌可以取消目标选择。
- 点击战场空白区域可以取消目标选择，但不能误触结束回合。

### 作用范围预览

对于全体敌人、全体友军、自身和无需目标的卡牌：

- 选中卡牌后直接显示实际作用范围。
- 群体目标使用统一的范围高亮，而不是逐个要求玩家点击。
- 目标预览不能提前改变 HP、护盾或状态数值。

### 操作锁定

以下期间应锁定出牌、换牌、丢弃和结束回合：

- 出牌分镜播放期间。
- 敌人行动播放期间。
- 命中顿帧和连续动作回放期间。
- 胜负遮罩出现后。

锁定时保留界面位置，只降低按钮亮度并显示忙碌状态，不能让操作区重新排版。

## 十、全局状态反馈

页面需要让玩家随时知道当前是否可以操作：

- 玩家行动阶段：显示可操作状态。
- 目标选择阶段：显示当前卡牌和目标要求。
- 换牌阶段：显示“选择一张手牌换牌”。
- 丢弃阶段：显示“选择一张手牌丢弃”。
- 敌人行动阶段：显示行动中并锁定输入。
- 动画播放阶段：显示短暂的演出锁定，不重复弹出提示。
- 手牌已满：抽牌相关反馈显示手牌上限，而不是静默失败。
- 费用不足：卡牌和费用区同时反馈，但不使用大面积遮罩。
- 无可用目标：卡牌详情中说明原因，并禁止进入无效目标选择。

这些反馈优先使用局部高亮、颜色、图标和短文本，不使用遮挡战场的大型提示框。

## 十一、需要新增或调整的组件

建议按模块拆分，避免继续把所有 HUD 逻辑堆在 `BattleScreen` 中：

- `BattleHeader`：回合、时刻和系统入口。
- `ManaPreview`：当前费用、悬停卡牌费用和使用后剩余费用。
- `ChallengePanel`：挑战图标组和挑战详情浮层。
- `BondPanel`：羁绊图标组、等级状态和完整等级详情浮层。
- `PileButton`：抽牌堆、弃牌堆、消耗堆的统一按钮外壳。
- `PileDrawer`：牌堆查看面板。
- `BattleActions`：换牌、丢弃和结束回合。
- `TargetingFeedback`：目标高亮、作用范围和目标提示。
- `BattleStatusOverlay`：玩家阶段、敌人行动、动画锁定等局部状态提示。
- `CardInfoPanel`：保留现有组件职责，但重新设计位置、尺寸和内容层级。

现有 `AllyBar`、`HandCard`、`CombatantView` 和战斗镜头演出继续保留，由新的布局组件组合，而不是重写角色立绘和手牌内部表现。

## 十二、数据接线要求

### 已有数据可以直接使用

- `BattleState.round`：当前回合。
- `BattleState.tick`：当前时刻。
- `BattleState.resources`：当前费用。
- `BattleState.draw`：抽牌堆。
- `BattleState.hand`：当前手牌。
- `BattleState.discard`：弃牌堆。
- `BattleState.exhaust`：消耗堆。
- `BattleState.redrawsThisRound`：本回合换牌次数。
- `BOND_DEFS`、`activeBonds`、`nextTier`：羁绊定义、当前等级和下一档。

### 需要补充战斗快照的数据

挑战事件目前属于探索阶段的战斗签数据。进入战斗时需要把当前已选挑战的展示信息复制到战斗会话快照中，至少包括：

- 挑战 id。
- 挑战名称。
- 挑战图标。
- 挑战描述。
- 实际生效的战斗改造或收益加成。

这样战斗 UI 只依赖本场战斗数据，战斗结束、刷新或探索页面切换时也不会丢失挑战展示。

### 费用预览

费用预览由 UI 根据当前选中或悬停卡牌计算，不需要修改战斗规则：

```text
remainingMana = currentMana - selectedCard.cost
```

实际出牌仍然调用战斗 store，UI 只负责预览和状态反馈。

## 十三、暂不纳入本轮设计的内容

- 战斗记录区。
- 战斗日志查看器。
- 伤害历史统计。
- 战斗中实时修改羁绊或装备的功能。
- 战斗中途撤离规则，除非引擎后续增加对应 action。

本轮的完成标准是：玩家无需离开战斗页面，就能清楚知道当前回合、时刻、费用、挑战、羁绊、手牌、牌堆状态和当前可执行操作；同时中央战场、角色立绘和手牌仍然是视觉重点。
