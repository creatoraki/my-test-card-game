# 事件奖惩清单

> **用途**：重新设计探索事件功能模块前的奖惩底表。把养成、战斗、探索三条线上所有能拿来做奖励和惩罚的东西盘一遍，逐条标注「事件层现在能不能发、走哪个效果、落到哪个口袋」。
>
> **真相点**：事件层的能力边界由 `src/explore/types.ts` 的 `ExploreEffect` 定义（34 个成员），实际结算由 `src/explore/session.ts` 的 `applyEffect()` 执行。本文所有数值均抄自代码。
>
> **本文不定义具体事件**，只定义可用的原材料。具体事件池见同目录下各地图的成长 / 生存 / 经济 / 风险 / 战斗事件文档。

## 〇、阅读约定

### 1. 奖励的三种落点

事件给出的东西不是都直接进背包，落点决定了玩家能不能拒绝、会不会占格：

| 落点 | 字段 | 玩家体验 | 典型效果 |
| --- | --- | --- | --- |
| **即时生效** | 直接改 `ExploreState` / `party` | 没有确认步骤，浮层里只看到一行结算摘要 | 治疗、掉血、粒子增减、经验、污染 |
| **待拾取框** | `pendingLoot` | 浮层里列出实物，玩家逐件拾取，**可以放弃**；拾取时占背包格，背包满则拿不了 | `GAIN_ITEM`、`ROLL_DROP`（事件默认 `defer = true`）、`GRANT_EQUIP`、`GRANT_MODULE` |
| **待办奖励队列** | `pendingActions` | 需要玩家再做一次决策（指定角色 / 从候选里挑一件），处理完才能确认节点 | `GAIN_EXP_ONE`、`HEAL_ONE`、`FORGE_DRAW`、`EQUIP_OFFER`、`RELIC_OFFER`、`REFORGE_BOND` 等 |

另有两个特殊落点：

- `pendingPickup`（**强制取舍框**）：背包装不下的溢出物，以及 `GRANT_RELIC` / `GRANT_RANDOM_RELIC` 投放的遗物走这里。非空时 UI 强制打开背包进「替换模式」，玩家必须腾格或丢弃，**不能整体放弃**。
- 直接进 `backpack`：只有 `FORCE_ITEM` 走这条路，无视 `defer`。

### 2. 什么算真的到手

| 收益 | 何时落袋 | 团灭时 |
| --- | --- | --- |
| 经验 | 每场战斗 / 每个节点结算后即时入账 | **保留** |
| 居民积分 `loot` | 撤退或通关回城时才转进城镇 | **全丢**（`EXPLORE_RULES.wipe.lootKept = 0`） |
| 背包实物 | 活着回城才进仓库 | **全丢** |
| 已寄件 `shipped` | 通过投递口寄回，立即安全 | **保留**（背包玩法唯一的保险） |
| 永久损伤（HP / 体力极限 / 污染 / 怪癖） | 回城时回填角色档案 | 照样记账 |

### 3. 名词对照

- **净化粒子 `energy`**：唯一的难度轴，整体设计前提是单向消耗（事件可以少量回补，但不该出现稳定的回粒子循环）。
- **体力极限 `hpLimit`**：生命三段的中间段（`hp ≤ hpLimit ≤ maxHp`）。永久损伤，跨远征继承。
- **掉落系数 K**：随机掉落表的产出旋钮，只作用于 `ROLL_DROP` 和战斗战利品，**不作用于 `GAIN_ITEM` 的指名实物**。

## 二、养成线可用奖励

### 2.1 经验

**是什么**：角色的可用经验池（`CharacterState.exp`）。角色**不设等级、不加属性点**，经验只有两个去处。

**用途与价格**（`engine/rules.ts` RULES.deck）：

| 去处 | 价格 |
| --- | --- |
| 升卡组等级（0→6） | 100 / 300 / 500 / 800 / 1200 / 1700 |
| 扩充卡组（抽卡三选一） | 今日首次 50，之后按次数递增 |
| 精简卡组（删卡） | 今日首次 100，每日每次 +50 |
| 降低最小卡组下限（8→5） | 80 / 160 / 240 |
| 模组制造 | 每个配方 200（`data/moduleCrafting.ts`） |

**事件层怎么发**：

- `GAIN_EXP_PARTY { amount }`：**存活角色各**得 amount，进 `pendingExp`，回城统一入账。阵亡者不发。
- `GAIN_EXP_ONE { amount }`：进待办队列，玩家指定一名存活角色。

**量级参考**：战斗经验 = 敌人 exp 之和 × 能量档位倍率。小怪 11-14、精英 30-32、BOSS 80，三小怪一场约 36。现有成长事件的全队档在 8-12、单人档在 25-30，即「单人档 ≈ 一场小怪战」。

### 2.2 卡组直接操作

| 效果 | 结算 | 备注 |
| --- | --- | --- |
| `FORGE_DRAW` | 待办：指定角色 → 摇稀有度 → 出 3 张专属候选 → 选 1 张入卡组 | 不消耗经验；稀有度权重由该角色卡组等级决定 |
| `FORGE_REMOVE` | 待办：指定角色 → 永久删 1 张卡 | 不能删到最小卡组下限以下 |
| `PURIFY_CARDS { scope, count }` | 待办：净化污染卡 | `"one"` 指定一人，`"party"` 全队各 count 张 |

**硬约束**（发卡类奖励必须知道）：稀有度限携 普通 20 / 罕见 6 / 稀有 3；同名副本上限 3 / 2 / 1；两者同时满足才能入卡。卡组等级**只**改抽卡时的稀有度权重，不能突破限携。

### 2.3 装备

| 效果 | 结算 | 落点 |
| --- | --- | --- |
| `GRANT_EQUIP` | 随机开一件装备（吃 K 与品质右移，带随机羁绊与词条 roll） | 待拾取框 |
| `EQUIP_OFFER { count, slot? }` | 公开 count 件候选，玩家挑一件；`slot` 可限定武器 / 防具 / 饰品 | 待办 |
| `REFORGE_BOND { bias? }` | 免费重铸一件已穿戴装备的羁绊词条；`bias` 可偏 `offense` / `defense` | 待办 |

**成本对照**（据点里做同样的事要花什么，用来给事件奖励定价）：

- 升阶到精良：两种槽位通用材料 + 地区 low 材料 ×1 + 300 积分
- 升阶到稀有 / 史诗 / 传说：槽位材料 + 蓝晶 ×3 / 蓝晶 ×3 / 红晶 ×3 + 600 / 1200 / 2400 积分
- 重铸羁绊：地区 boss 材料（拾荒核心）×1 —— **只有 BOSS 掉**，所以「免费重铸一次」是一份相当贵的奖励，不该当中档收益随便发

装备在背包里**占 2 格**。

### 2.4 模组

- `GRANT_MODULE`：随机一件 1 阶通用模组（攻击力 / 治愈力 / 穿甲 / 暴击 / 精准 / 淬毒 / 燃烧，统一 `fine`），进待拾取框。**不吃品质右移**（1 阶池里没有别的档可移）。
- 也可以用 `GAIN_ITEM("module-crate-t1")` 给「1 阶模组箱」消耗品，让玩家自己选时机开。

**注意区分**：`category: "module"`（成品模组，装到卡上）与 `category: "material"`（制造原料）是两回事。角色专属模组（速攻 / 弃牌 / 落差 / 卫星 / 借星 / 瞄准 / 催熟 / 组装 ABCD / 急诊 / 回响）**只能制造，不进随机投放池**。

### 2.5 材料四类

| 类别 | 具体物品 | 用途 | 商店 / 回收台 |
| --- | --- | --- | --- |
| 通用材料 | 魔方 `logic-cube`、齿轮 `standard-gear`、电池 `standard-battery`、弹簧 `coil-spring`、磁铁 `magnet` | 模组制造、装备升阶 | 商店可买 |
| 水晶 | 绿 `green-crystal` / 蓝 `blue-crystal` / 红 `red-crystal` | 科技树、建筑升级、高阶升阶 | **商店不卖、回收台不收** |
| 地区特色材料 | 霓虹灯管 `neon-tube`(low)、压缩废块 `compacted-block`(mid)、拾荒核心 `salvage-core`(boss) | low → 1 阶升阶；mid → 模组制造；boss → 羁绊重铸 | 不进交易终端候选池 |
| 换金物 | 铜币 50 / 银币 200 / 金币 500 | 回城回收台直接变现，**不进仓库** | 只有回收价 |

换金物售价受科技 `scrap-price` 加成：每级 +10%。

**事件层怎么发**：

- `GAIN_ITEM { itemId, count }` —— 指名实物，**不吃 K**。写死几件就是几件，适合确定性奖励。
- `ROLL_DROP { table }` —— 掷一张掉落表，**吃 K 与品质右移**；表里每条 `chance` 会被 `chance × K` 放大成期望件数（超过 1 就必掉且可能多掉）。适合「翻箱倒柜看运气」。**目前正式事件池一次都没用过**，见第六章。

### 2.6 居民积分

`GAIN_LOOT { amount }`：数额先乘能量档位倍率（1.0 / 1.1 / 1.2 / 1.35 / 1.6），再累加进 `session.loot`；活着回城才落袋，团灭全丢。

**用途与价格**：

| 去处 | 价格 |
| --- | --- |
| 统一商店购买 / 刷新 | 刷新基价 100 / 90 / 80（按设施科技） |
| 科技树「训练点强化」10 级 | 300 起步，每级 +300，满级 3000（另需水晶） |
| 营养舱疗养 | 每人次 100 |
| 复苏舱复活阵亡队员 | 200（档案、装备、卡上模组全部重置） |
| 装备升阶 | 300 / 600 / 1200 / 2400 |
| 圣水池净化诅咒遗物 | 按稀有度 80 / 140 / 220 / 360 / 600 + 水晶 |

**当前设计口径**：战斗**不直接掉积分**（`loot.perEnemy = 0`），积分主线是「换金物带回据点出售」，只有 BOSS 通关给 60。事件里的 `GAIN_LOOT` 是一条完全可用但绕开主线的直给通道 —— 用它要清楚这一点。

### 2.7 训练点 / 小队徽章 —— 缺口

训练点 = 已唤醒角色卡组等级取前 N 名之和 + 科技 `training-points` 等级（每级 +1）。花在小队徽章的扇形天赋树上（初心者徽章 6 链 22 节点，方向为手牌上限 / 换牌 / 待机 / 费用 / 抽牌 / 起手）。

**事件层完全没有入口。** 见第六章。

### 2.8 遗物

| 效果 | 结算 | 落点 |
| --- | --- | --- |
| `GRANT_RELIC { relicId }` | 指名一件；已拥有则**回落为居民积分 +10** | 强制取舍框 |
| `GRANT_RANDOM_RELIC { rarity? }` | 从祝福遗物池随机抽一件未拥有的；池空回落积分 +10 | 强制取舍框 |
| `RELIC_OFFER { count?, relicIds?, rarity? }` | 公开 count 件候选挑一件；候选取光时回落积分 +10 | 待办 |

祝福遗物占背包格，按 `ownedRelicIds` 去重。现有 13 件基础祝福遗物（余温火柴、幸运铜币、磨刀石、猎人的独眼、储能水晶、钟摆、压缩饼干、运动鞋、干燥药草、幸运纽扣、磁化护符、黑铁钉、蓄热石），另有教程池与罕见池。

### 2.9 消耗品与临期食品

| 族 | 效果（各稀有度当前共用一档） | 商店价 |
| --- | --- | --- |
| 糖块 `sugar-cube-*` | 回复一名存活角色 20% 生命 | 30 |
| 医疗包 `medical-kit-*` | 修复一名存活角色 10 点体力极限，并回等值 HP | 200 |
| 圣水 `holy-water-*` | 降低一名存活角色 15 点污染值 | 50 |
| 果汁 `fruit-juice-*` | 占位，**当前不可使用** | — |

六种临期食品：牛奶 `milk`、面包 `bread`、可乐 `cola`、汉堡 `hamburger`、炸鸡 `fried-chicken`、披萨 `pizza`。它们同时是三种东西：

1. **交易终端的货币**（12 种服务各自指定收哪种食品、收几个）；
2. **成长 / 生存事件高级选项的门槛**（`EventChoice.cost` 校验背包里有没有这件食品）；
3. **野餐食谱与隐藏 NPC 的钥匙**（整趟一次野餐，最多投 4 件食品，命中 6 个隐藏食谱之一得随机祝福遗物；没命中全队回 10 点 HP）。

所以「给食品」是一种**延迟兑现的奖励**，实际价值取决于后面遇到什么终端，适合作为中低档收益。

## 三、战斗线可用奖励

事件层能不能直接发战斗奖励？不能，但可以用 `START_NODE_BATTLE { tier? }` 触发一场节点战斗，整套战斗产出随之而来。这一节记录「触发一场战斗到底等于给了多少东西」。

### 3.1 战利品 boon 表

战斗胜利后按每名敌人的 `boonTable` 并行掷点，`chance × K` 决定件数：

| 档位 | 治疗露珠 | 装备箱 | 模组箱 | 卡牌候选 |
| --- | --- | --- | --- | --- |
| 小怪 | 0.30 | 0.10 | 0.05 | 0.15 |
| 精英 | 0.50 | 0.30 | 0.15 | 0.30 |
| BOSS | 0.80 | 1.00 | 0.50 | 1.00 |
| 宝箱怪 | — | 1.00（械匣） | — | 1.00（牌匣） |

- 治疗露珠：全队各回 5 点 HP（`boons.healDewAmount`），不复活。
- 卡牌候选：每场最多 1 次（`boons.cardOfferCap`），按存活角色生成。
- 装备箱 / 模组箱：进战利品盘。

### 3.2 敌人掉落表

| 档位 | 掉落表 |
| --- | --- |
| 小怪通用 | 绿晶 0.20 / 地区 low 材料 0.25 / 铜币 0.40 / 1 阶模组箱 0.03 / **诅咒遗物「断针罗盘」0.04** + 逐怪一种通用材料 0.05 |
| 精英通用 | 蓝晶 0.60 / 地区 mid 材料 0.50 / 铜币 0.40 / 1 阶模组箱 0.08 |
| BOSS | 红晶 1.00 / 地区 boss 材料 1.00 / 金币 0.50 / 银币 0.60 / 齿轮 0.60 |

注意：**诅咒遗物已经在小怪掉落表里**，是既有的投放渠道；事件层反而没有对应手段。

### 3.3 掉落系数 K

K =（K_energy + Σ挑战词条加成 + 同花加成）× `kGlobal`，**全加法合成**（`kGlobal` 当前 1.0）。

| 粒子档位 | 名称 | 阈值 | 敌人过载层数 | K_energy |
| --- | --- | --- | --- | --- |
| 1 | 充盈 | ≥80 | 0 | 1.00 |
| 2 | 稳定 | ≥60 | 1 | 1.10 |
| 3 | 衰减 | ≥40 | 2 | 1.20 |
| 4 | 告急 | ≥20 | 3 | 1.35 |
| 5 | 枯竭 | ≥0 | 4 | 1.60 |

K → 品质权重五档表（`explore/rules.ts` drop.qualityTable），K ≤ 1.05 时普通 85%，K > 2.4 时普通降到 38%、精良升到 43%。

**这条同时是奖励也是惩罚**：粒子掉得越狠，敌人越强，但产出品质越好。事件设计「额外消耗粒子」时要意识到它顺带抬高了后续所有掉落。

### 3.4 挑战词条

`engine/challenges/defs.ts` 定义的战斗内自选目标，达成直接加进 K：

- 0.3 档（基础）：慈悲、不改初衷、养精蓄锐
- 0.4-0.5 档（中等）：克制、聚焦、轻装上阵……
- 0.6-0.8 档（高难）：需要专门卡组或抽牌运

事件层无法直接授予或修改挑战词条 —— 见第六章缺口。

### 3.5 战斗经验与积分

- 经验 = 敌人 `exp` 之和 × 能量档位倍率，胜利后**即时入账**，团灭也不退。
- 积分：普通战斗 `perEnemy = 0`，BOSS 通关 `bossBonus = 60`。

## 四、探索线可用奖励

### 4.1 净化粒子

| 效果 | 说明 |
| --- | --- |
| `MODIFY_ENERGY { amount }` | 正负皆可，上限 100 |
| `EventChoice.energyDelta` | 选项自带的增减，**不含**每节点固定消耗 |
| `SKIP_NODE_COST { nodes }` | 接下来 N 个节点免除基础粒子消耗 |

固定消耗口径：每结算 1 个节点按推进段扣 **3 / 3 / 4 / 5**（越深越贵）；每进行 1 个战斗回合 −1（BOSS 战豁免）；投递口寄件 −5。起始 100。

**定价参考**：一个第 4 段节点 = 5 粒子；`SKIP_NODE_COST 2` 在深段约等于回 8-10 粒子，是很强的收益，别当小奖发。

### 4.2 治疗五件套

| 效果 | 作用 | 注意 |
| --- | --- | --- |
| `HEAL_PARTY { percent }` | 全队按 maxHp 百分比回 HP | 不复活阵亡者；封顶 hpLimit |
| `HEAL_ONE { percent, full? }` | 待办，玩家指定一人 | `full: true` 直接回满 |
| `HEAL_ONE_FULL { othersPercent }` | 自动挑当前生命比例最低者回满，其余按百分比 | **不由玩家指定**，目标由系统选 |
| `HEAL_LIMIT_PARTY { percent }` | 全队修体力极限并同步回等额 HP | 修的是永久损伤，价值远高于同数值的回血 |
| `HEAL_LIMIT_ONE { percent?, full? }` | 待办，指定一人修体力极限 | 同上 |

**关键区别**：回 HP 是「这趟远征的续航」，修体力极限是「永久资产的修复」。据点里修体力极限要花营养舱 100 积分一人次，事件里给 `HEAL_LIMIT_*` 要按这个价来估。

### 4.3 状态清理

| 效果 | 作用 |
| --- | --- |
| `CURE_QUIRK { scope, count? }` | 治疗怪癖（永久 debuff），`one` 指定一人 / `party` 全队各 count 个 |
| `REDUCE_POLLUTION { scope, amount }` | 降低污染值，拖延生病与怪癖 |
| `PURIFY_CARDS { scope, count? }` | 净化污染卡，切断污染源头 |

三者是同一条惩罚链上的三个解法：净化卡 = 断源、降污染 = 拖延、治怪癖 = 善后。事件设计上应当有意识地把三种解法分给不同事件，别让一个事件包治百病。

### 4.4 背包与保险

- `OPEN_CHUTE`：开启投递口，玩家在背包面板里选物品寄回据点，**团灭也保得住**，代价 5 粒子。整个游戏唯一的止损手段。
- 背包固定 24 格；有效负重 = 已占格数 − 队伍负重适应，命中 −⌊P/4⌋、先手 −⌊P/10⌋（`engine/stats.ts`；注意《角色养成设计.md》里写的 P/2、P/5 是旧口径，以代码为准）。

### 4.5 跨轮挑战契约

`START_TRIAL { trial }`：接下即刻生效，本轮与下一轮的全部战斗背着负面属性修正，下一轮推进战斗打完立即结算奖励并撤掉修正。中途撤离或战败 = 白扛不发奖。可叠加。

现有 4 份契约（`data/exploreTrials.ts`），统一 2 轮、接下花 5 粒子：

| 契约 | 代价 | 奖励（加权二选一） |
| --- | --- | --- |
| 过载限流阀 | 全队攻击力 −30% | 魔方 ×1 + 电池 ×2 ｜ 随机祝福遗物 |
| 医疗协议封锁 | 治愈力 −35%、治愈强度 −20 | 医疗包 ×2 + 圣水 ×1 ｜ 随机祝福遗物 |
| 重力校准场 | 闪避 −20、格挡 −15 | 随机装备 + 弹簧 ×2 ｜ 随机祝福遗物 |
| 感应干扰塔 | 命中 −15、暴击 −20 | 随机模组 + 磁铁 ×1 ｜ 随机祝福遗物 |

**硬约束**：`mods` 对每名角色各叠一次，所以**绝不能写 `burdenAdapt`**（小队合计属性，三人队会被叠三倍），也不碰 `maxHp`（会让当前血高于上限）。安全项：attack / healPower / healBoost / shieldBoost / dodgeRate / blockRate / hitRate / critRate / critDamage / precision / initiative / armorPen。

### 4.6 交易终端

`OPEN_SHOP`：拉起本事件登记的服务槽位（最多两个）。12 种服务全部用**临期食品**付费：

| 服务 | 货币 | 内容 |
| --- | --- | --- |
| 通用材料商店 | 面包 ×1 | 2 选 1 材料 |
| 临期食品商店 | 可乐 ×1 | 2 选 1 食品 |
| 水晶交易站 | 炸鸡 ×1 | 2 选 1 水晶 |
| 消耗品商店 | 汉堡 ×1 | 2 选 1 消耗品 |
| 武器商店 | 汉堡 ×1 | 2 选 1 武器（占 2 格） |
| 包裹快递服务 | 披萨 ×1 | 开投递口，最多寄 6 件 |
| 医疗服务 | 牛奶 ×1 | 全队回 20% HP |
| 随机团队 BUFF | 可乐 ×1 | 公开 3 个候选，随机得 1 件祝福遗物（运动鞋 50 / 磨刀石 30 / 幸运纽扣 20） |
| 抽卡服务 | 披萨 ×1 | 指定角色三选一 |
| 删卡服务 | 面包 ×2 | 指定角色删 1 张 |

### 4.7 流程类

- `START_NODE_BATTLE { tier? }`：把节点变成一场战斗，档位默认 t1 60% / t2 40%。
- `END_REGION`：立即结束本轮推进，直接进本轮推进战斗（「逆流净化机」的设想，**当前无事件使用**）。

## 五、可用惩罚

按「可逆性」从轻到重排列。事件设计时，重惩罚必须配重奖励，且必须让玩家在选项文案里读得到风险。

### 5.1 净化粒子损失（轻，可换算）

负 `MODIFY_ENERGY` / 负 `energyDelta`。掉档带来双向后果：敌人叠过载（提高攻击伤害与闪避），自己的收益倍率反而上升。**它不是纯粹的惩罚，而是「用难度换产出」的旋钮** —— 用它做惩罚时要注意别变相给玩家送 K。

### 5.2 当前 HP 损失（中，可治疗）

`DAMAGE_PARTY_PERCENT { percent }`：全队按 **maxHp** 百分比掉血，至少 1 点。

三个必须知道的副作用：

1. **可以打死人** —— HP 归零即 `alive = false`，角色永久离队；全员倒下直接触发团灭。
2. 掉血时若 `hpLimit > hp`，会把 `hpLimit` 压到当前 hp —— 也就是说**掉血会顺带削体力极限**。
3. 按 maxHp 而非当前 HP 计算，残血队伍吃同一个百分比时风险高得多。

现有风险事件的档位大致是 8%-25%，做重惩罚时不建议超过 30%。

### 5.3 体力极限损失（重，难修复）

没有独立效果类型，通过 5.2 的副作用产生。永久损伤，跨远征继承。修复渠道只有三条：医疗包（10 点）、`HEAL_LIMIT_*` 事件、据点营养舱（100 积分／人次）。

### 5.4 卡组污染链（最重的软惩罚）

`CONTAMINATE_CARDS { count?, each? }`：

- 默认：全队总共污染 count 张随机未污染卡。
- `each: true`：**每名角色各**污染 count 张 —— 三人队实际是 3× count，两种语义差别很大，文案必须写清。

后续链条：

```
污染卡进手牌 → 该角色 +2 污染值
污染值 ≥ 100 → 归零 → 永久生病（攻击/防御/先手 −10%）+ 随机获得 1 个永久怪癖
```

怪癖三选一，最多 5 个：

| 怪癖 | 效果 |
| --- | --- |
| 乏力 🥱 | 攻击力 −20% |
| 佝偻病 🦴 | 最大生命 −20% |
| 树懒 🦥 | 先手 −20% |

生病是**不可逆**的（怪癖可以治，生病状态不能）。这是全游戏最重的长期惩罚链，一次性污染 3 张以上应当配相当高的回报。

### 5.5 背包惩罚

| 效果 | 后果 |
| --- | --- |
| `DISCARD_SLOTS { slots }` | 强制丢弃若干格，**按稀有度从低到高**丢（装备同稀有度靠后），`undroppable` 物品豁免。背包空时无事发生 |
| `FORCE_ITEM { itemId, count }` | 强制拾取，直接进背包、不进可放弃的拾取框；背包满则溢出到强制取舍框，玩家必须腾格 |

《沉重的负担》`heavy-burden`：`undroppable: true`，丢弃、强制丢弃、放弃拾取、投递口寄件四条出口全部关闭，纯占 1 格。它的实际伤害是抬高负重 → 命中与先手惩罚，一整趟甩不掉。

### 5.6 诅咒遗物（事件层缺手段）

现有 5 件，占背包格，按 `RelicSpec` 在战斗或探索时触发：

| 遗物 | 效果 | 净化去向 |
| --- | --- | --- |
| 断针罗盘 | 每抵达一个节点额外 −2 粒子 | → 普通祝福 |
| 静电寄生体 | 战斗中全队命中 −10 | → 普通祝福 |
| 空腔核心 | 每打出 3 张牌，全队 +1 污染 | → 精良祝福 |
| 沉影锚 | 每场战斗胜利额外 −4 粒子 | → 稀有祝福 |
| 渗血刻印 | 每受 2 次敌方攻击，全队 −2 HP | → 稀有祝福 |

诅咒遗物是**有出路的惩罚**：带回据点投进圣水池（3 个位、2 天、按稀有度 80-600 积分 + 水晶）可以换成更高稀有度的祝福遗物。这让它非常适合做「高风险高回报」事件的代价 —— 但**事件层目前发不出来**，只有小怪掉落表能产出。

### 5.7 挑战契约 debuff

见 4.5。特点是「先扛后发奖、中途放弃全亏」，是唯一一种玩家主动接下的惩罚。

### 5.8 终局惩罚

| 情形 | 后果 |
| --- | --- |
| 角色阵亡 | 永久离开编队；所穿三件装备掉进战利品盘；复苏舱 200 积分可复活，但档案、装备、卡上模组**全部重置** |
| 团灭 | 背包全丢、本趟积分全丢（`lootKept: 0`）；已寄件保留；经验保留 |
| 战败 | 即团灭 |

## 六、当前缺口与建议

### 6.1 有能力却没用上（改动量：仅数据）

以下效果在 `applyEffect()` 里都已实现并可用，但在正式事件池 `data/exploreEvents.ts` 里**零命中**（用 grep 可复核）：

| 效果 | 为什么值得用 | 建议投放位置 |
| --- | --- | --- |
| `ROLL_DROP` | 事件产出目前全是写死的 `GAIN_ITEM`，完全不吃 K，导致「深潜提高掉落品质」这条核心循环在事件上失效。用它可以让搜刮类事件随粒子档位变强 | 成长事件的「翻找 / 搜刮」类选项；风险事件的高风险回报 |
| `GAIN_LOOT` | 唯一的积分直给通道。适合做「卖情报 / 领赏金」这种不产出实物的经济事件，还能不占背包格 | 经济事件、NPC 事件 |
| `DISCARD_SLOTS` | 现在唯一的背包惩罚是《沉重的负担》加格，缺少「反过来抢东西」的手段。它对满背包玩家是重惩罚、对空背包玩家几乎无感，天然是「贪多的人先付账」 | 风险事件、经济事件的违约后果 |
| `OPEN_CHUTE` | 目前只有交易终端的快递服务能开。事件里给一次免费寄件，是很有分量的「保险」奖励 | 生存事件、深段成长事件 |
| `SKIP_NODE_COST` | 唯一能对抗深段 4/5 粒子阶梯的手段，正好呼应「隐匿通道」这类路线事件 | 路由类事件（`kind: "route"`） |
| `GRANT_EQUIP` / `GRANT_MODULE` | 目前只有教程池和挑战契约在用。正式事件里装备只能靠 `EQUIP_OFFER`（要玩家再决策一次），缺少「直接掉一件」的轻量档 | 成长事件的中档收益 |
| `RELIC_OFFER` / `GRANT_RELIC` | 遗物目前只有 `GRANT_RANDOM_RELIC`（2 处）。指名与三选一能让遗物投放有设计意图，而不是纯随机 | 深段成长事件、隐藏 NPC |
| `HEAL_ONE_FULL` | 「救主力」这个语义现在没人用；它自动挑伤最重者，正好适合「只够救一个人」的叙事 | 生存事件 |
| `END_REGION` | 「立即结束本轮推进进入战斗」是一种独特的止损/加速手段，设计上早有构想（逆流净化机）但没落地 | 终局类事件（`minRound: 5`） |
| `START_TRIAL` | 只有挑战节点在用。普通事件里给一份契约，可以让非挑战节点也有跨轮决策 | 风险事件 |

### 6.2 没有能力（需要加效果类型）

每条的落点都一样：`explore/types.ts` 的 `ExploreEffect` 加一个成员 + `session.ts` 的 `applyEffect` 加一个分支（部分还需要 store 层消费）。

| 想要的奖惩 | 建议效果 | 落点与改动量 | 备注 |
| --- | --- | --- | --- |
| 发放诅咒遗物 | `GRANT_CURSE_RELIC { relicId?, rarity? }` | 小。复用 `grantRelic()`，只是候选池换成 `CURSE_RELIC_DEFS`，并去掉「已拥有回落积分」的祝福专用逻辑 | 最推荐先做的一条：它把「高风险高回报」事件的代价从「掉血」扩展成「带一个麻烦回家」，而且有圣水池这条出路，惩罚不绝望 |
| 扣居民积分 | 允许 `GAIN_LOOT` 传负数（现在会被倍率放大成负得更多，需要单独走一条不吃倍率的分支） | 极小 | 用于「过路费 / 赎金 / 贿赂」类经济事件 |
| 直接给训练点 | `GAIN_TRAINING_POINT { amount }` | 中。训练点是 `townStore` 派生值（卡组等级 + 科技等级），不是可累加字段，需要先在 `SquadTalentState` 里加一个 `bonusPoints` 存量，再由 store 层消费 | 目前事件对小队天赋树完全没有影响力，是养成线上最大的空白 |
| 封锁入口通道 | `BLOCK_LANES { count, duration? }` | 中。`RouteBoard.blockedLanes` 字段与 `canEnterLane()` 判定**都已实现**，只缺一个写入方；需要决定作用于本轮还是下一轮 | 现有唯一一条「影响路线本身」的惩罚，注释里点名了「塌落的隔断」这个设想却从未落地 |
| 增减背包格 | `MODIFY_BACKPACK_SLOTS { delta, duration }` | 大。背包容量当前是常量 `RULES.burden.backpackSlots = 24`，要改成会话字段并贯穿 `addToContainer` 的所有调用点 | 收益不确定，优先级最低 |
| 授予 / 剥夺挑战词条 | `GRANT_CHALLENGE { id }` | 中。挑战词条在开战时生成，需要把「预置词条」传进 `battleSetup` | 可以做出「接下这个委托，下一场必须做到 X」的委托型事件 |
| 给消耗品之外的据点资源 | 无需新类型 | 无 | 水晶、材料本来就能用 `GAIN_ITEM` 发，只是事件池没发过 |

### 6.3 建议的推进顺序

1. **先补数据层**（6.1 全部）：不动一行逻辑，事件池就能用上 11 种闲置能力。
2. **再加诅咒遗物与扣积分**（6.2 前两条）：改动量都很小，能立刻补上「负面奖励」这个空缺。
3. **训练点与封锁通道**放到事件模块重构的同一批里做，因为它们会影响事件的分类与保底规则。
4. 背包格增减暂不做。

## 七、事件设计约束（写给下一轮）

从现有设计文档与代码注释里提炼的硬规矩，重设计时逐条照做：

**数据结构**

1. `NodeEvent.energyDelta` 必须与 `choices[0].energyDelta` 一致 —— 前者是节点卡上的预览，后者才是真正结算的值，写岔了玩家看到的代价就是假的。
2. `EventChoice.desc` 当前 UI **不渲染**（选项不预告得失），所有玩家必须知道的信息只能写进 `description` 正文或 `story`。
3. 风险事件每个策略内的 `chance` 权重累加为 100，直接写设计文档里的百分数。
4. `depth: [a, b]` 是深度分层的唯一声明处；`minRound` 只给终局类事件用。
5. 挑战契约的 `mods` 不得包含 `burdenAdapt` 与 `maxHp`。

**设计口径**

6. 额外消耗粒子只改变操作成本，**不得提高奖励品质** —— 否则「花粒子买好东西」会架空粒子作为难度轴的定位。
7. 每个事件 2-3 个选项，每个选项至少 2 种随机结果，每个选项和每个结果都要有独立故事文案。
8. 成长事件里约 1/3 - 1/2 的节点配隐藏 NPC（由 `hiddenRest` 登记指定食品）。
9. 奖励一律「先展示、后领取」：实物进拾取框、待办进队列，处理完才能确认节点。
10. 不设难度段位，事件在允许的推进段内随机可用。

**平衡口径**

11. 指名实物用 `GAIN_ITEM`（不吃 K），随机搜刮用 `ROLL_DROP`（吃 K）—— 两者的选择本身就是一次平衡决策。
12. 修体力极限 / 免费重铸 / 免除节点消耗，这三类的实际价值远高于同规模的材料奖励，不要当中档收益发。
13. 惩罚要给出路：污染有圣水与净化服务、诅咒遗物有圣水池、负重有投递口。设计新惩罚时先确认它的出路在哪。
