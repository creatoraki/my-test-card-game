# 《霓虹都市》废弃楼层：成长事件池（食品试探版）

> 地图背景：未来世界超级科技公司大楼的一层。楼层已经废弃，但清运传送带、维修工位、储物柜、训练终端和上一批苏醒者留下的营地仍在执行旧工单。
>
> 本文重新定义废弃楼层的成长事件。成长事件不再只是“看到物品就捡走”，而是让玩家在稳定收益、有限食品和长期构筑之间做判断：先选择一个不需要食品的处理方式；如果现场线索足够明确，也可以投入一份食品，尝试唤醒隐藏流程。猜中对应食品时，获得构筑级奖励；猜错时食品消耗，但仍得到保底收益，并在结果中学会本事件的正确答案。

## 一、设计目标

废弃楼层的成长事件围绕四条成长主线展开：

1. **资源搜集**：获得通用材料、废弃楼层地区材料、消耗品、装备和少量临期食品。
2. **经验分配**：在全队均衡成长和单角色集中培养之间选择。
3. **免费卡组锻造**：获得一次不消耗经验的角色专属三选一卡牌机会。
4. **定向装配**：从公开的装备候选中选择当前队伍真正需要的装备。

成长事件的正反馈不是单纯提高掉落数量，而是让玩家经历以下循环：

```text
观察现场线索 → 选择安全收益或投入食品 → 猜中后获得构筑选择权 → 下一场战斗验证成长
```

安全选项必须始终有价值；食品试探必须有足够高的上限；猜错之后必须留下可用于下一次远征的知识。玩家不应因为没有食品而错过唯一正确答案，也不应因为猜错一次就觉得系统只是在收食品税。

## 二、统一规则

### 1. 事件边界

- 所有事件使用 `category: growth`、`kind: loot`。
- 每个事件提供两个不需要食品的安全选项：`A` 是主选项，`B` 是替代选项。
- 每个事件额外提供一次可选的**食品试探**：玩家从当前远征背包中选择一种临期食品并投入 `×1`。
- 食品试探不是经济事件交易，不显示报价，不把正确食品写在按钮或选项说明里。玩家只能根据现场线索、旧工单、机器用途和之前远征留下的知识进行判断。
- 食品试探每个事件只能进行一次。投入食品后无论猜中或猜错，都不能继续尝试其他食品。
- 没有任何临期食品时，食品试探按钮显示不可用，但 A/B 仍然可以正常选择。
- 正确食品由事件 ID 固定决定，不随随机种子、净化粒子档位或本次远征变化。这样玩家在失败后学到的答案能够在下一次远征中形成长期正反馈。
- 猜错时只消耗投入的食品并结算保底奖励，不额外扣粒子、不掉 HP、不污染卡牌、不强制丢弃物品，也不改变路线。
- 猜错结果必须揭示该事件的正确食品，并把答案写入事件记录；揭示答案不是额外奖励，而是让失败转化为信息。
- 猜中时获得“保底奖励 + 大额奖励”。大额奖励优先提供选择权、免费卡组锻造、定向装备或两个成长轴的组合，不只增加同一种材料的数量。
- 食品试探不返还食品，也不稳定产出食品、居民积分或路线服务，避免形成食品循环。
- 事件可以同时奖励实物与经验，但必须分别写明目标、数量和背包占用。经验不占背包，装备占 2 格，其他实物按物品定义占格。
- 事件不直接提高角色基础面板。经验只能进入角色经验池；装备和卡牌仍通过现有养成规则发挥作用。

### 2. 三种处理方式的关系

| 处理方式 | 是否消耗食品 | 作用 | 设计定位 |
| --- | --- | --- | --- |
| `A` 主选项 | 否 | 稳定、完整的单轴收益，通常消耗少量粒子 | 不猜也能获得的可靠成长 |
| `B` 替代选项 | 否 | 较轻、较窄或不同方向的收益，通常节省粒子或背包 | 根据当前队伍和背包做取舍 |
| 食品试探 | 是，食品 ×1 | 猜错得保底，猜中得保底加大奖 | 用有限资源换取更高成长上限 |

推荐的价值关系如下，作为平衡时的相对目标而不是硬公式：

- `A/B` 的安全收益记为约 `1.0` 个成长单位。
- 食品试探猜错时的保底收益约为 `0.5-0.8` 个成长单位，不能是空结果。
- 食品试探猜中时的总收益约为 `2.0-3.0` 个成长单位，并至少包含一个选择型或构筑型奖励。
- 食品试探不能同时拿到 A、B 和大奖；它是第三条处理路径，不是对 A/B 的额外叠加。
- 深段事件的大奖可以高于上述比例，但应通过更强的选择权体现，而不是无限堆叠数量。

### 3. 食品线索与答案记忆

食品是探索中的有限交易资源，但在成长事件中承担的是“识别旧系统协议”的作用。线索必须足够合理，让玩家在观察后有机会猜中；不能用与现场无关的随机答案制造挫败。

| 食品 | 玩家可学习的主题线索 | 适合关联的成长现场 |
| --- | --- | --- |
| 牛奶 | 冷链、营养、睡眠舱、基础生命配给 | 营地、配给线、休息记录 |
| 面包 | 普通员工、早班工位、清运班、基础维修 | 传送带、维修工单、轮班训练 |
| 可乐 | 企业终端、权限识别、办公系统、私人柜机 | 储物柜、档案库、适配终端 |
| 汉堡 | 高热量作业、训练考核、重载设备 | 模拟舱、压块机、重型工位 |
| 炸鸡 | 上一批远征者、临时营地、特殊团队配给 | 苏醒者营地、遗留团队记录 |
| 披萨 | 主管权限、完整团队配给、高级装备仓 | 主管配装室、深段构筑终端 |

设计答案只存在于事件数据和设计文档中，不能直接出现在玩家首次看到的描述里。玩家猜错后，结果文案应明确写出“该系统实际识别的是{正确食品}”，让下一次遇到同类场景时能做出更好的判断。

### 4. 结果展示

每个事件的结果分为三层：

1. **玩家见到的**：只描述现场，不提前写出正确食品或尚未结算的掉落。
2. **玩家可以选择的**：A/B 只描述行动和可预见的代价；食品试探只写“投入一份食品，尝试唤醒隐藏流程”。
3. **选择后的结果**：根据实际结果写出带回的物品、经验目标、卡牌名、装备候选、食品是否猜中以及背包装入状态。

食品试探的结果至少区分：

- 猜错：`你投入的{实际食品}没有被旧协议识别。食品已经消耗；系统只完成了保底流程，获得{保底奖励}。屏幕最后显示：该设备需要{正确食品}。`
- 猜对：`{实际食品}通过了旧协议。隐藏流程启动；除保底收益外，你们获得{大额奖励}。`
- 背包部分装入：写明实际进入背包的物品和暂存待处理的物品。
- 背包全部装不下：写明没有物品进入背包；经验、卡牌机会和候选选择仍按各自规则结算。
- 卡组没有合法目标：不消耗尚未确定的免费卡组机会；事件改用本表写明的经验替代奖励。
- 定向装配没有合法候选或前置条件不满足：在选择前显示不可用，不扣材料、不扣食品；若食品试探猜中，则按本事件的替代奖励结算。

### 5. 粒子与深度

- 每结算一个节点固定消耗 3 点净化粒子；本文所有 `E` 只记录额外变化。
- A/B 的 `energyDelta` 与事件表中的 E 规则保持一致，节点卡预览 A 的额外粒子变化。
- 食品试探默认 `E = 0`，食品本身就是代价。即使猜错，也不再追加粒子或其他负面效果。
- `[1, 2]` 事件以资源搜集、基础装备和小额经验为主，正确食品使用面包、牛奶、可乐等常见食品。
- `[1, 3]` 事件以经验分配、免费卡组锻造和资源组合为主。
- `[2, 4]` 事件以免费卡组锻造、定向装配和“经验 + 物资”双轴奖励为主，正确食品可以使用汉堡、炸鸡或披萨。
- 首图可以生成 12 个成长事件中的若干个；整张路由图至少生成 3 个成长节点的保底规则由探索模式统一处理。
- 成长事件不承担治疗、污染卡牌净化、普通路线改写、居民积分交易或风险事件式的概率惩罚。

## 三、奖励组合策略

### 1. 浅段：用同类升级建立学习感

浅段事件的食品试探不要直接给最强装备，而是给“安全收益的明显升级版”。例如：

- 齿轮 ×1 → 猜中后齿轮 ×1 + 地区材料 ×1。
- 全队经验 +8 → 猜中后全队经验 +8，并额外获得一件指定材料。
- 一个安全物资 → 猜中后物资 + 经验，让食品试探第一次产生双轴成长。

玩家第一次猜中时能立刻感受到食品有价值，但不会因为一份普通食品直接跳过成长曲线。

### 2. 中段：用双轴奖励制造取舍

中段事件的大奖同时推进两个成长轴，例如：

- 经验 + 地区材料。
- 材料 + 装备候选。
- 经验 + 免费三选一卡牌。

双轴奖励比单纯“材料 ×5”更容易形成正反馈，因为玩家能把奖励立即转化为当前队伍的实际计划。

### 3. 深段：用选择权制造记忆点

深段食品试探的大奖优先采用以下形式：

- 从 3 件公开装备候选中选择 1 件。
- 为指定角色开启一次免费的三选一卡牌机会。
- 选择“全队经验包”或“单角色高额经验包”。

选择权比单次随机掉落更能形成记忆点：玩家不是被动看到一个数字变大，而是亲手把奖励接到当前构筑上。

### 4. 食品消耗的机会成本

- 食品同时是经济事件的支付资源，因此玩家需要考虑“现在试探成长事件”还是留给后面的确定交易。
- 成长事件的食品试探不提供确定兑换报价，不应比经济事件的稳定服务更划算。
- 正确食品越稀有，大奖越偏向构筑选择；常见食品的大奖偏向材料、经验和普通候选。
- 任何食品都不应在成长事件中稳定回流，否则玩家会形成“获得食品 → 继续试探”的无限循环。

## 四、成长事件

以下 12 个事件均为可抽取的成长事件。每个事件的“设计答案”只供数据和设计使用，玩家首次进入时不显示。

### 1. 废品分拣带

**ID：** `sorting-belt`　**节点名称：** 清运分拣廊　**段位：** `[1, 2]`　**设计答案：** 面包（`bread`）

**玩家见到的：**

传送带还在缓慢空转。机械臂把办公椅、外壳碎片和失去编号的设备推入不同分拣仓。传送带尽头挂着一块早班清运表，表格上反复出现“开工前配给”和“未领取早餐”的旧记录。

**玩家可以选择：**

- **A：搬空分拣仓。** 停机检查分拣仓，额外消耗 2 点净化粒子，取得更完整的设施材料。
- **B：只挑轻的。** 不停机，只从传送带边缘拿走一枚齿轮，不额外消耗粒子。
- **食品试探：投递一份食品。** 消耗食品 ×1，尝试让清运系统开启早班配给协议。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 搬空分拣仓 | 齿轮 ×2；50% 概率额外获得磁轨衬层 ×1 | -2 |
| B 只挑轻的 | 齿轮 ×1 | 0 |
| 食品试探猜错 | 保底：齿轮 ×1；结果中揭示正确食品为面包 | 0 |
| 食品试探猜对 | 保底奖励 + 磁轨衬层 ×1、分拣识别片 ×1 | 0 |

**正反馈重点：** 猜中后同时获得一件地区材料和一件识别组件，能帮助玩家为后续装备或经济事件做准备；它不会在浅段直接发放装备。

### 2. 故障维修工位

**ID：** `repair-bench`　**节点名称：** 维修校准工位　**段位：** `[1, 2]`　**设计答案：** 面包（`bread`）

**玩家见到的：**

工位的高压隔离组件还固定在校准架上，维修工具插在原位。终端不断循环播放“普通维修班早餐已领取”的提示，旁边的工单则停在最后一次线路校准。

**玩家可以选择：**

- **A：完成线路校准。** 接通工位，按普通维修班的流程收取维护材料，额外消耗 2 点净化粒子。
- **B：取走备用电池。** 不启动整套工位，只拿走仍有电量的标准电池，不额外消耗粒子。
- **食品试探：恢复维修班授权。** 消耗食品 ×1，尝试让终端执行完整维修班奖励流程。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 完成线路校准 | 断路陶芯 ×1、导电印墨 ×1 | -2 |
| B 取走备用电池 | 电池 ×1 | 0 |
| 食品试探猜错 | 保底：导电印墨 ×1；结果中揭示正确食品为面包 | 0 |
| 食品试探猜对 | 保底奖励 + 断路陶芯 ×1、全队存活角色经验 +8 | 0 |

**边界：** 这里是维修材料回收，不是装备拆解、装备重组、材料精炼或模组装配。食品猜中后奖励的是材料和经验，不生成新的加工系统。

### 3. 未清空的储物柜

**ID：** `locker-row`　**节点名称：** 旧员工储物柜列　**段位：** `[1, 2]`　**设计答案：** 可乐（`cola`）

**玩家见到的：**

一整排储物柜仍按工位编号排列。锁没有锈死，缝隙里露出标准逻辑单元、备用电池和资源芯片的指示灯。柜门内侧贴着旧员工饮料条码的扫描说明。

**玩家可以选择：**

- **A：逐个撬开。** 额外消耗 2 点净化粒子，检查私人终端、备用电池和识别组件。
- **B：只开没锁的。** 不破坏锁具，取走一块糖块，不额外消耗粒子。
- **食品试探：提交员工条码配给。** 消耗食品 ×1，尝试让柜列终端开放高级储物格。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 逐个撬开 | 魔方 ×1；50% 概率获得电池 ×1 | -2 |
| B 只开没锁的 | 普通糖块 `sugar-cube-c` ×1 | 0 |
| 食品试探猜错 | 保底：魔方 ×1；结果中揭示正确食品为可乐 | 0 |
| 食品试探猜对 | 保底奖励 + 电池 ×1、分拣识别片 ×1 | 0 |

### 4. 冷链配给回收线

**ID：** `ration-reclamation-line`　**节点名称：** 废弃营养配给线　**段位：** `[1, 2]`　**设计答案：** 牛奶（`milk`）

**玩家见到的：**

冷藏箱仍按员工编号排列，机械臂把牛奶、面包和封装凝胶从一条传送带推向另一条。加热程序已经失效，但包装上的营养标签和冷链温度记录仍然完整。

**玩家可以选择：**

- **A：恢复旧配给。** 额外消耗 2 点净化粒子，让配给线吐出仍可使用的补给。
- **B：拆下包装回收。** 关闭冷链，拆下传送带边的封装凝胶，不额外消耗粒子。
- **食品试探：提交冷链校准样本。** 消耗食品 ×1，尝试让配给线启动高级营养档案。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 恢复旧配给 | 牛奶 ×1、面包 ×1、封装凝胶 ×1 | -2 |
| B 拆下包装回收 | 封装凝胶 ×2 | 0 |
| 食品试探猜错 | 保底：封装凝胶 ×1；结果中揭示正确食品为牛奶 | 0 |
| 食品试探猜对 | 保底奖励 + 全队存活角色经验 +6、封装凝胶 ×1 | 0 |

**边界：** 该事件可以提供少量临期食品，但食品试探本身不返还食品；配给线不能成为食品无限循环来源。

### 5. 上批苏醒者营地

**ID：** `sleeper-camp`　**节点名称：** 临时苏醒者营地　**段位：** `[1, 3]`　**设计答案：** 炸鸡（`fried-chicken`）

**玩家见到的：**

倒下的办公隔断后面还留着几只睡袋，烧尽的加热片被整齐叠在一旁。桌面上的牛奶和面包没有吃完，一台营地终端则反复显示“撤离前高热量团队配给未完成”。

**玩家可以选择：**

- **A：收拢遗物。** 带走桌面上尚未开封的牛奶 ×1、面包 ×1。
- **B：阅读训练记录。** 放弃食品，读完上一批苏醒者的训练摘要；所有存活上阵角色获得经验 +8。

### 奖励节奏

- 前 4 个浅段事件让玩家学习“现场主题对应食品”的基本语言，并用材料、消耗品和小额组合奖励及时反馈。
- 第 5-7 个事件把食品试探接到经验分配和资源组合，让玩家开始把食品和角色长期计划联系起来。
- 第 8-11 个事件把正确食品转成免费卡组机会或定向装备选择，作为深入路线的主要诱因。
- 第 12 个事件用“材料 + 经验”收束深段奖励，给不缺卡牌或装备的玩家另一个有价值的猜中结果。
- 同一张路线图内不应连续出现多个完全相同的大奖类型；探索模式的事件抽取应尽量让玩家在材料、经验、卡牌和装备之间形成路线选择。
- 当玩家连续猜错时，至少能得到保底物资或经验，并在历史记录中累计答案知识；当玩家猜中时，奖励应能在下一场战斗或下一次卡组操作中被立即感知。

## 六、数据接入备注

当前 `NodeEvent.choices` 只有两个选项，食品试探不建议伪装成第三个普通 `EventChoice`，否则会破坏节点卡只预览 `choices[0]`、UI 固定两个按钮和现有结算逻辑。建议在数据层新增独立的可选字段：

```ts
foodTrial?: {
  answerItemId: string;
  fallbackEffects: ExploreEffect[];
  jackpotEffects: ExploreEffect[];
}
```

建议的效果类型：

```ts
export type ExploreEffect =
  | { type: "GRANT_EXP"; mode: "party" | "focus"; amount: number }
  | { type: "FREE_CARD_FORGE"; characterId?: string }
  | { type: "DIRECTED_EQUIPMENT_PICK"; candidateCount: 2 | 3 }
  // 继续保留现有 HEAL / GAIN_ITEM / ROLL_DROP 等效果
```

推荐的结算流程：

1. 检查当前阶段、事件是否已结算以及背包中是否存在玩家选择的食品。
2. 先扣除玩家选择的食品；食品不足时不产生任何结算。
3. 将玩家选择的 `itemId` 与事件固定的 `answerItemId` 比较。
4. 猜错时执行 `fallbackEffects`，并在结果文案中揭示正确食品。
5. 猜对时先执行保底效果，再执行 `jackpotEffects`。
6. 实物统一进入现有背包和 `pendingPickup` 流程；经验交给角色经验发放流程。
7. 免费三选一卡牌机会复用角色专属卡池、稀有度权重、限携校验和选卡落袋流程。
8. 定向装配打开公开候选界面；候选生成后锁定，选择和装备落袋必须原子结算。
9. 事件完成后记录玩家选择的食品、是否猜中、保底结果、大奖结果和正确答案是否已揭示。

食品试探需要新增的实际效果接口可以保持最小化：

- 消耗一个指定 `itemId` 的背包物品。
- 发放经验。
- 打开一次免费卡组锻造。
- 打开一次定向装备候选。

不需要把食品试探扩展成新的风险事件系统，也不需要改变 `EventCategory`。它仍然是成长事件内部的一条可选处理路径。

## 七、明确排除项

本事件池不包含以下方向：

- 材料精炼、材料转化或材料加工。
- 装备拆解、装备重组、装备重铸。
- 模组装配或模组槽位处理。
- 羁绊调校、羁绊升级或关系数值改变。
- 蓝图、技术记录或长期解锁型收藏。
- 治疗、污染卡牌净化、普通路线改写、居民积分交易。
- 猜错后的额外伤害、污染、扣粒子、强制丢弃或路线惩罚。
