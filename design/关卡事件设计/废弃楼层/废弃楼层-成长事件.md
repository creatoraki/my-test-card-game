# 《霓虹都市》废弃楼层：成长事件池（食品交换版）

> 地图背景：未来世界超级科技公司大楼的一层。楼层已经废弃，但清运传送带、维修工位、储物柜、训练终端和上一批苏醒者留下的营地仍在执行旧工单。
>
> 本文重新定义废弃楼层的成长事件。成长事件不再只是“看到物品就捡走”，而是让玩家在稳定收益、路线推进和有限食品之间做判断：先完成事件本身，再决定前往下一个节点、前往当前路线图终点，或在这里稍微吃点食物休息一下。选择吃东西时，正确的食品会吸引需要它的路过 NPC，NPC 会用奖励交换这份食品；食品不匹配时，食品照常损失，但不会得到额外奖励。

## 一、设计目标

废弃楼层的成长事件围绕四条成长主线展开：

1. **资源搜集**：获得通用材料、废弃楼层地区材料、消耗品、装备和少量临期食品。
2. **经验分配**：在全队均衡成长和单角色集中培养之间选择。
3. **免费卡组锻造**：获得一次不消耗经验的角色专属三选一卡牌机会。
4. **定向装配**：从公开的装备候选中选择当前队伍真正需要的装备。

成长事件的正反馈不是单纯提高掉落数量，而是让玩家经历以下循环：

```text
观察现场线索 → 完成事件 → 决定推进、直达路线图终点或原地吃东西 → 食品命中后与路过 NPC 交换奖励 → 下一场战斗验证成长
```

事件本身的安全选项必须始终有价值；食品交换应当提供路线推进之外的额外机会，但不能变成稳定的食品回收循环。玩家不应因为没有食品而无法完成事件，也不应因为拿错食品就得到隐藏的保底收益。

## 二、统一规则

### 1. 事件边界

- 所有事件使用 `category: growth`、`kind: loot`。
- 每个事件提供两个不需要食品的处理选项：`A` 是主选项，`B` 是替代选项。玩家必须先完成其中一个选项，事件奖励按原有规则结算。
- 事件完成后，玩家进行一次互斥的后续选择：**前往下一个节点**、**前往当前路线图终点**，或**在这里稍微吃点食物休息一下**。
- 选择“在这里稍微吃点食物休息一下”时，玩家从当前远征背包中拿出一种临期食品 `×1`。拿出的食品无论是否匹配都会从背包中消耗。
- 食品选择不是事件内的额外选项，也不改变已经完成的事件奖励；它只决定是否有机会遇到需要这份食品的路过 NPC。
- NPC 需要的食品由当前成长事件固定决定，不随随机种子、净化粒子档位或本次远征变化。玩家可以根据现场线索、旧工单和机器用途进行判断。
- 食品匹配时，遭遇需要该食品的路过 NPC；NPC 消耗这份食品，并以本事件定义的奖励进行交换。
- 食品不匹配时，只消耗玩家拿出的食品，不产生 NPC、奖励、保底收益或路线惩罚；不额外扣粒子、不掉 HP、不污染卡牌、不强制丢弃其他物品。
- 没有任何临期食品时，第三项后续选择显示不可用，但事件 A/B 和前两项路线选择仍然可以正常进行。
- 每个事件完成后只能进行一次后续选择；选择其中任一项后，不能在同一事件中改选其他路线或再次拿出食品。
- 食品交换不稳定产出食品、居民积分或路线服务，避免形成食品循环。
- 事件可以同时奖励实物与经验，但必须分别写明目标、数量和背包占用。经验不占背包，装备占 2 格，其他实物按物品定义占格。
- 事件不直接提高角色基础面板。经验只能进入角色经验池；装备和卡牌仍通过现有养成规则发挥作用。

### 2. 事件处理与后续选择的关系

| 阶段 | 是否消耗食品 | 作用 | 设计定位 |
| --- | --- | --- | --- |
| 事件 `A` 主选项 | 否 | 稳定、完整的单轴收益，通常消耗少量粒子 | 不使用食品也能获得的可靠成长 |
| 事件 `B` 替代选项 | 否 | 较轻、较窄或不同方向的收益，通常节省粒子或背包 | 根据当前队伍和背包做取舍 |
| 后续：前往下一个节点 | 否 | 沿当前路线继续推进 | 用已获得的事件收益换取后续节点机会 |
| 后续：前往当前路线图终点 | 否 | 放弃剩余节点，直接结束当前路线图 | 保留资源并尽快进入路线图后续流程 |
| 后续：在这里稍微吃点食物休息一下 | 是，食品 ×1 | 匹配时与路过 NPC 交换奖励；不匹配时只损失食品 | 用有限食品换取一次额外奖励机会 |

推荐的价值关系如下，作为平衡时的相对目标而不是硬公式：

- `A/B` 的安全收益记为约 `1.0` 个成长单位。
- “前往下一个节点”和“前往当前路线图终点”不额外发放奖励，价值来自路线选择本身。
- 食品不匹配时的收益为 `0`；不能为了安慰玩家添加材料、经验或保底物资。
- 食品匹配并完成 NPC 交换时，奖励约为 `1.0-2.0` 个成长单位，深段可以通过选择权或构筑型奖励提高上限。
- 食品交换奖励不能同时领取事件 `A/B` 的另一份收益；事件奖励与食品交换奖励属于两个不同结算阶段，但每阶段各自只能结算一次。
- 深段 NPC 的奖励可以高于上述比例，但应通过更强的选择权体现，而不是无限堆叠数量。

### 3. 食品线索与答案记忆

食品是探索中的有限交易资源，但在成长事件中承担的是“吸引特定路过 NPC”的作用。线索必须足够合理，让玩家在观察后有机会判断 NPC 需要什么；不能用与现场无关的随机答案制造挫败。

| 食品 | 玩家可学习的主题线索 | 适合关联的路过 NPC 与成长现场 |
| --- | --- | --- |
| 牛奶 | 冷链、营养、睡眠舱、基础生命配给 | 携带补给箱的休息 NPC；营地、配给线、休息记录 |
| 面包 | 普通员工、早班工位、清运班、基础维修 | 早班维修 NPC；传送带、维修工单、轮班训练 |
| 可乐 | 企业终端、权限识别、办公系统、私人柜机 | 携带终端的企业 NPC；储物柜、档案库、适配终端 |
| 汉堡 | 高热量作业、训练考核、重载设备 | 重载维修 NPC；模拟舱、压块机、重型工位 |
| 炸鸡 | 上一批远征者、临时营地、特殊团队配给 | 寻找团队配给的远征 NPC；苏醒者营地、遗留团队记录 |
| 披萨 | 主管权限、完整团队配给、高级装备仓 | 主管级维修 NPC；主管配装室、深段构筑终端 |

事件对应的 NPC 食品需求只存在于事件数据和设计文档中，不能直接出现在玩家首次看到的描述里。食品不匹配时，结果只记录食品已经损失且没有遇到 NPC，不展示正确食品、补偿奖励或其他额外信息。

### 4. 结果展示

每个事件的结果分为三层：

1. **玩家见到的**：只描述现场，不提前写出正确食品或尚未结算的掉落。
2. **玩家可以选择的**：A/B 只描述行动和可预见的代价；事件结算后再显示“前往下一个节点”“前往当前路线图终点”“在这里稍微吃点食物休息一下”三项后续选择。
3. **选择后的结果**：先写明事件 A/B 的结算，再根据后续选择写出路线去向，或食品是否遇到 NPC、NPC 交换的奖励以及背包装入状态。

在这里吃东西的结果至少区分：

- 食品不匹配：`你拿出的{实际食品}没有遇到需要它的 NPC。食品已经消耗；这次休息没有获得交换奖励。`
- 食品匹配：`路过的 NPC 正在寻找{实际食品}。NPC 收下食品，并用{交换奖励}与你们交换。`
- 背包部分装入：写明实际进入背包的物品和暂存待处理的物品。
- 背包全部装不下：写明没有物品进入背包；经验、卡牌机会和候选选择仍按各自规则结算。
- 卡组没有合法目标：不消耗尚未确定的免费卡组机会；NPC 交换改用本表写明的经验替代奖励。
- 定向装配没有合法候选或前置条件不满足：在选择前显示不可用，不扣材料、不扣食品；若 NPC 交换奖励包含装备选择，则按本事件的替代奖励结算。

### 5. 粒子与深度

- 每结算一个节点固定消耗 3 点净化粒子；本文所有 `E` 只记录额外变化。
- A/B 的 `energyDelta` 与事件表中的 E 规则保持一致，节点卡预览 A 的额外粒子变化。
- 事件完成后的三项后续选择默认 `E = 0`，食品本身就是“在这里稍微吃点食物休息一下”的代价。食品不匹配时不追加粒子或其他负面效果。
- `[1, 2]` 事件以资源搜集、基础装备和小额经验为主，正确食品使用面包、牛奶、可乐等常见食品。
- `[1, 3]` 事件以经验分配、免费卡组锻造和资源组合为主。
- `[2, 4]` 事件以免费卡组锻造、定向装配和“经验 + 物资”双轴奖励为主，正确食品可以使用汉堡、炸鸡或披萨。
- 首图可以生成 12 个成长事件中的若干个；整张路由图至少生成 3 个成长节点的保底规则由探索模式统一处理。
- 成长事件不承担治疗、污染卡牌净化、普通路线改写、居民积分交易或风险事件式的概率惩罚。

## 三、奖励组合策略

### 1. 浅段：用同类交换建立学习感

浅段事件的 NPC 食品交换不要直接给最强装备，而是给“路线收益之外的合理补充”。例如：

- 事件拿到齿轮 ×1 → 食品匹配后由 NPC 交换地区材料 ×1。
- 事件拿到全队经验 +8 → 食品匹配后由 NPC 交换额外一件指定材料。
- 事件拿到一个安全物资 → 食品匹配后由 NPC 交换经验，让食品第一次产生双轴成长。

玩家第一次遇到正确 NPC 时能立刻感受到食品有价值，但不会因为一份普通食品直接跳过成长曲线。

### 2. 中段：用双轴奖励制造取舍

中段事件的大奖同时推进两个成长轴，例如：

- 经验 + 地区材料。
- 材料 + 装备候选。
- 经验 + 免费三选一卡牌。

双轴奖励比单纯“材料 ×5”更容易形成正反馈，因为玩家能把奖励立即转化为当前队伍的实际计划。

### 3. 深段：用交换选择权制造记忆点

深段食品交换的 NPC 奖励优先采用以下形式：

- 从 3 件公开装备候选中选择 1 件。
- 为指定角色开启一次免费的三选一卡牌机会。
- 选择“全队经验包”或“单角色高额经验包”。

选择权比单次随机掉落更能形成记忆点：玩家不是被动看到一个数字变大，而是亲手把 NPC 的交换奖励接到当前构筑上。

### 4. 食品消耗的机会成本

- 食品同时是经济事件的支付资源，因此玩家需要考虑“现在在事件后休息并寻找 NPC”还是留给后面的确定交易。
- 成长事件的食品交换不提供确定兑换报价，不应比经济事件的稳定服务更划算。
- NPC 需要的食品越稀有，交换奖励越偏向构筑选择；常见食品的交换奖励偏向材料、经验和普通候选。
- 任何食品都不应在成长事件中稳定回流，否则玩家会形成“获得食品 → 继续交换”的无限循环。

## 四、成长事件

以下 12 个事件均为可抽取的成长事件。每个事件的“NPC需求食品”只供数据和设计使用，玩家首次进入时不显示。

每个事件都遵循同一结算顺序：

1. 玩家选择并完成事件 A 或 B，结算该选项的奖励。
2. 事件完成后，玩家选择“前往下一个节点”“前往当前路线图终点”或“在这里稍微吃点食物休息一下”。
3. 只有选择原地吃东西才会消耗一份食品并检查 NPC 是否出现；食品匹配时结算 NPC 交换奖励，不匹配时只消耗食品。

### 1. 废品分拣带

**ID：** `sorting-belt`　**节点名称：** 清运分拣廊　**段位：** `[1, 2]`　**NPC需求食品：** 面包（`bread`）

**玩家见到的：**

传送带还在缓慢空转。机械臂把办公椅、外壳碎片和失去编号的设备推入不同分拣仓。传送带尽头挂着一块早班清运表，表格上反复出现“开工前配给”和“未领取早餐”的旧记录。

**玩家可以选择：**

- **A：搬空分拣仓。** 停机检查分拣仓，额外消耗 2 点净化粒子，取得更完整的设施材料。
- **B：只挑轻的。** 不停机，只从传送带边缘拿走一枚齿轮，不额外消耗粒子。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 搬空分拣仓 | 齿轮 ×2；50% 概率额外获得磁轨衬层 ×1 | -2 |
| B 只挑轻的 | 齿轮 ×1 | 0 |
| 事件完成后 | 玩家选择前往下一个节点、前往当前路线图终点，或在这里稍微吃点食物休息一下 | 0 |

**食品交换：** 选择原地吃东西并拿出面包时，会遇到早班清运 NPC；NPC 用磁轨衬层 ×1、分拣识别片 ×1 交换面包。拿出其他食品时，只损失拿出的食品，不获得奖励。

**正反馈重点：** 交换成功后同时获得一件地区材料和一件识别组件，能帮助玩家为后续装备或经济事件做准备；它不会在浅段直接发放装备。

### 2. 故障维修工位

**ID：** `repair-bench`　**节点名称：** 维修校准工位　**段位：** `[1, 2]`　**NPC需求食品：** 面包（`bread`）

**玩家见到的：**

工位的高压隔离组件还固定在校准架上，维修工具插在原位。终端不断循环播放“普通维修班早餐已领取”的提示，旁边的工单则停在最后一次线路校准。

**玩家可以选择：**

- **A：完成线路校准。** 接通工位，按普通维修班的流程收取维护材料，额外消耗 2 点净化粒子。
- **B：取走备用电池。** 不启动整套工位，只拿走仍有电量的标准电池，不额外消耗粒子。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 完成线路校准 | 断路陶芯 ×1、导电印墨 ×1 | -2 |
| B 取走备用电池 | 电池 ×1 | 0 |
| 事件完成后 | 玩家选择前往下一个节点、前往当前路线图终点，或在这里稍微吃点食物休息一下 | 0 |

**食品交换：** 选择原地吃东西并拿出面包时，会遇到早班维修 NPC；NPC 用断路陶芯 ×1、全队存活上阵角色经验 +8 交换面包。拿出其他食品时，只损失拿出的食品，不获得奖励。

**边界：** 这里是维修材料回收，不是装备拆解、装备重组、材料精炼或模组装配。食品交换奖励的是材料和经验，不生成新的加工系统。

### 3. 未清空的储物柜

**ID：** `locker-row`　**节点名称：** 旧员工储物柜列　**段位：** `[1, 2]`　**NPC需求食品：** 可乐（`cola`）

**玩家见到的：**

一整排储物柜仍按工位编号排列。锁没有锈死，缝隙里露出标准逻辑单元、备用电池和资源芯片的指示灯。柜门内侧贴着旧员工饮料条码的扫描说明。

**玩家可以选择：**

- **A：逐个撬开。** 额外消耗 2 点净化粒子，检查私人终端、备用电池和识别组件。
- **B：只开没锁的。** 不破坏锁具，取走一块糖块，不额外消耗粒子。

| 选择 | 结算效果 | E |
| --- | --- | ---: |
| A 逐个撬开 | 魔方 ×1；50% 概率获得电池 ×1 | -2 |
| B 只开没锁的 | 普通糖块 `sugar-cube-c` ×1 | 0 |
| 事件完成后 | 玩家选择前往下一个节点、前往当前路线图终点，或在这里稍微吃点食物休息一下 | 0 |

**食品交换：** 选择原地吃东西并拿出可乐时，会遇到携带终端的企业 NPC；NPC 用电池 ×1、分拣识别片 ×1 交换可乐。拿出其他食品时，只损失拿出的食品，不获得奖励。

### 4. 冷链配给回收线

**ID：** `ration-reclamation-line`　**节点名称：** 废弃营养配给线　**段位：** `[1, 2]`　**NPC需求食品：** 牛奶（`milk`）

**玩家见到的：**

冷藏箱仍按员工编号排列，机械臂把牛奶、面包和封装凝胶从一条传送带推向另一条。加热程序已经失效，但包装上的营养标签和冷链温度记录仍然完整。

**玩家可以选择：**

- **A：恢复旧配给。** 额外消耗 2 点净化粒子，让配给线吐出仍可使用的补给。

### 奖励节奏

- 前 4 个浅段事件让玩家学习“现场主题对应食品”的基本语言，并用材料、消耗品和小额组合交换及时反馈。

- 第 8-11 个事件把 NPC 交换转成免费卡组机会或定向装备选择，作为深入路线的主要诱因。

- 同一张路线图内不应连续出现多个完全相同的 NPC 交换奖励类型；探索模式的事件抽取应尽量让玩家在材料、经验、卡牌和装备之间形成路线选择。
- 食品不匹配时只损失食品，不提供保底或额外信息；食品匹配时，交换奖励应能在下一场战斗或下一次卡组操作中被立即感知。

## 六、数据接入备注

当前 `NodeEvent.choices` 只有两个事件处理选项，事件完成后的路线与食品选择不建议伪装成第三个普通 `EventChoice`，否则会破坏节点卡只预览 `choices[0]`、UI 固定两个事件按钮和现有结算逻辑。建议在数据层新增独立的后续动作字段：

```ts
postEventActions?: {
  nextNode: true;
  routeEnd: true;
  foodExchange?: {
    requiredItemId: string;
    npcId: string;
    exchangeEffects: ExploreEffect[];
  };
}
```

建议的效果类型：

```ts
export type ExploreEffect =
  | { type: "GRANT_EXP"; mode: "party" | "focus"; amount: number }
  | { type: "FREE_CARD_FORGE"; characterId?: string }
  | { type: "DIRECTED_EQUIPMENT_PICK"; candidateCount: 2 | 3 }
  // 继续保留现有 HEAL / GAIN_ITEM / ROLL_DROP 等效果
```

推荐的结算流程：

1. 检查当前阶段、事件是否已结算；事件 A/B 结算完成后，进入后续动作选择。
2. 选择“前往下一个节点”时推进当前路线；选择“前往当前路线图终点”时结束当前路线图。
3. 选择“在这里稍微吃点食物休息一下”时，检查背包中是否存在玩家选择的食品。
4. 食品不足时不产生任何结算；食品存在时先扣除玩家选择的食品。
5. 将玩家选择的 `itemId` 与事件固定的 `requiredItemId` 比较。
6. 食品不匹配时只记录食品消耗和没有遇到 NPC，不发放任何奖励，不追加路线、粒子或状态变化。
7. 食品匹配时生成指定 `npcId`，执行 `exchangeEffects`，并记录 NPC 交换结果。
8. 实物统一进入现有背包和 `pendingPickup` 流程；经验交给角色经验发放流程。
9. 免费三选一卡牌机会复用角色专属卡池、稀有度权重、限携校验和选卡落袋流程。
10. 定向装配打开公开候选界面；候选生成后锁定，选择和装备落袋必须原子结算。
11. 后续动作完成后锁定本事件，不能再次推进、直达终点或拿出其他食品。

食品交换需要新增的实际效果接口可以保持最小化：

- 提供“前往下一个节点”“前往当前路线图终点”“在这里稍微吃点食物休息一下”三个后续动作。
- 消耗一个指定 `itemId` 的背包物品。
- 按 `requiredItemId` 判断是否生成指定 NPC。
- 发放经验。
- 打开一次免费卡组锻造。
- 打开一次定向装备候选。

不需要把食品交换扩展成新的风险事件系统，也不需要改变 `EventCategory`。它是成长事件完成后的一个后续动作，不是成长事件的第三个处理选项。

## 七、明确排除项

本事件池不包含以下方向：

- 材料精炼、材料转化或材料加工。
- 装备拆解、装备重组、装备重铸。
- 模组装配或模组槽位处理。
- 羁绊调校、羁绊升级或关系数值改变。
- 蓝图、技术记录或长期解锁型收藏。
- 治疗、污染卡牌净化、普通路线改写、居民积分交易。
- 食品不匹配后的奖励、额外伤害、污染、扣粒子、强制丢弃或路线惩罚。
