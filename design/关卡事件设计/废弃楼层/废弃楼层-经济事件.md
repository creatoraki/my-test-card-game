# 《霓虹都市》废弃楼层：经济事件池

> 地图背景：未来世界超级科技公司大楼的一层。废弃楼层里的自动售货机、回收商、医疗终端和收费门禁仍把队伍识别为“可以交易的内部人员”，但它们只接受还保留人类社会识别价值的临期食品。
>
> 本文定义经济事件的交易模型，不把“商店”简单写成免费奖励。每笔交易都必须同时明确支付物、服务或商品、背包要求、使用次数和可能的风险；未写出的效果不自动结算。

## 一、统一规则

### 1. 经济事件的职责边界

- 所有普通经济事件使用 `category: economy`、`kind: merchant`。
- 经济事件只负责把**临期食品**兑换成一次性服务、探索物资、有限情报或特殊入口服务。
- 经济事件不使用居民积分。居民积分只在据点交易终端、角色修复和设施建设中使用；探索中的支付必须是具体食品和具体数量。
- 经济事件不把一种食品换成另一种食品。营养膏、净化安瓿、急救组件等是消耗品，不是“食品余额”的不同表现。
- 经济事件不提供长期成长、卡牌抽取、卡组升级、普通路线便利、重掷、选择权、剧情关系、任务物品、维修、精炼、重铸或持续规则修改。
- 允许提供的战斗相关服务必须写明作用范围和持续时间，例如“下一场战斗开始前生效”；不能写成未定义的“战斗强化”。首图第一批模型暂不依赖此类服务。
- “有限情报”只能揭示隐藏区域、隐藏宝库或特殊事件节点的位置，不改写普通路线，不直接移动队伍。
- “特殊入口服务”只能开启已经被情报标记的隐藏区域或解除特殊入口封锁，不跳过节点、不免除节点粒子消耗、不重排路线。

### 2. 服务模型与商店模型

经济事件必须先区分“买服务”和“买物品”，两者的随机性来源不同：

- **固定服务：** 支付明确食品后得到明确结果。治疗、污染卡牌净化、位置情报、特殊入口开启和投递都属于固定服务；服务目标可能由玩家选择，但结果规则不随机。
- **随机商店：** 商店固定声明接受哪些食品作为货币，并固定声明货架的物品类别；具体库存物品在商店实例生成时随机产生。随机的是货架内容，不是玩家付款后的隐藏结果。
- 事件层仍保留 `进入服务/交易` 与 `离开` 两类处理。固定服务可以在进入后提供 2-3 个确定报价；随机商店进入后显示货架，不把每个随机货位伪装成独立事件分支。
- 玩家第一次打开商店时生成本次商店实例的货架，之后关闭、重新打开、切换角色或返回节点都不能刷新。货架结果必须写入探索状态并随本次远征保持不变。
- 商店货架在生成后立即公开：具体物品、稀有度、占格、价格、剩余数量和风险全部可见。玩家是在“买不买这件随机出现的东西”，不是在“付钱赌一个未知结果”。
- 普通商店每次抵达最多购买 2 个不同货位，风险商店最多购买 1 个货位；货位售出后不能补货，也不能重复购买。
- 一笔交易必须原子结算：先检查食品、货位状态、背包空位、服务目标和本次远征使用次数，再扣食品，最后发放商品或服务。任一前置条件不满足时，不扣食品，也不发放半份结果。
- 购买结果无法装入背包时，先进入现有替换流程；玩家没有腾出空间并确认拿取前，不得扣除食品。装备按 2 格计算，其余物品按物品定义计算。
- 交易完成后立即写入事件记录，防止重复打开目录再次购买。随机货架不能通过重新生成节点或重新打开浮层重掷。
- 固定服务不进行隐藏成功率检定。风险商店可以有污染等附加风险，但风险必须和货架、价格一起在确认前公开。

### 3. 食品支付口径

下表只用于定价和内容平衡，运行时仍然检查具体食品 `itemId` 和数量，不能把它们压成一个通用食品值。

| 食品 | 设计定位 | 常见支付用途 |
| --- | --- | --- |
| 牛奶 | 基础食品 | 小额治疗、基础消耗品 |
| 面包 | 基础食品 | 基础材料、低档服务 |
| 可乐 | 标准包装饮料，终端识别度高 | 医疗机器人、售货机、情报终端 |
| 汉堡 | 高热量食品，价值较高 | 重点治疗、装备和急救服务 |
| 炸鸡 | 稀缺高热量食品 | 高档材料、特殊入口、风险交易 |
| 披萨 | 组合食品，价值最高且占用较大 | 高价值装备、投递和高级入口服务 |

- 同种食品可以按物品规则堆叠；食品占格、团灭损失和远征结束清除规则沿用[《临期食品设计》](../../物品设计/消耗品及货币/临期食品.md)。
- 支付必须写成“可乐 ×2”这类确定形式，不得写“消耗 2 点食品”“任意食品 ×2”或“按食品价值支付”。
- 经济事件不稳定产出食品。偶尔由其他事件获得的食品是有限支付资源，不应被商店循环兑换成更多食品。

#### 固定货币组与随机货架

商店的货币类型是商店属性，不随货架随机变化。下表中的食品集合是**唯一可接受的支付类型**；价格可以在这些食品中组合，但不能接受集合之外的食品。

| 商店模型 | 固定接受的食品 | 随机货架范围 | 货位数 | 每次最多购买 |
| --- | --- | --- | ---: | ---: |
| 基础回收商店 | 面包、牛奶 | 废料、消耗品 | 3 | 2 |
| 高级科技商店 | 可乐、炸鸡 | 模组材料、装备 | 3 | 2 |
| 黑屏风险商店 | 炸鸡、披萨 | 装备 | 2 | 1 |

- 货位物品从对应范围内随机生成；随机池可以使用具体物品集合或 `familyId`，但不能越过商店声明的类别。
- 货位价格使用预先定义的价格模板，例如“可乐 ×1”“炸鸡 ×1”“可乐 ×1 + 炸鸡 ×1”。价格模板只使用该商店的固定货币组，不创建通用食品价值。
- 货架随机生成使用探索会话的可复现随机源，并在第一次打开时锁定。相同事件实例不会因为 UI 重挂或重新进入而改变库存。
- `family` 货位的品质受当前净化粒子档位影响；指名物品货位的具体物品在货架生成时确定，不在支付后再次抽取。
- 货架可以出现多个同类货位，但每个货位都是独立库存；购买一个货位不会刷新或合并其他货位。

### 4. 背包、目标与服务失败

- 商品型交易必须在报价中标明占格：营养膏、净化安瓿、急救组件、材料和普通物品各占 1 格；装备占 2 格。若未来新增物品，沿用物品定义的 `slots`，不在事件文档另造一套占格规则。
- 治疗和净化服务可以不占背包，但仍要明确目标。全队治疗按最大 HP 计算，只回复当前 HP；重点治疗默认作用于当前生命比例最低的存活角色；卡牌净化只处理污染卡牌，不自动回血。
- 服务没有合法目标时，交易不能完成。例如队伍没有污染卡牌时，净化服务应在支付前置检查阶段标记为不可购买，而不是扣食品后再给空结果。
- 队伍没有存活角色时，不能使用治疗、净化或交易服务；远征的阵亡处理由探索流程负责。
- 交易不能因为“背包满”自动丢弃已有物品，也不能静默把装备降成材料。需要替换时必须使用现有背包替换流程。

### 5. 深度与风险分层

| 事件档位 | 允许段位 | 设计目的 |
| --- | --- | --- |
| 基础交易 | `[1, 2]` | 用低档食品换稳定的治疗、消耗品和普通材料。 |
| 中档交易 | `[1, 3]` | 提供装备、高档材料或有限情报，但要求玩家规划食品和背包。 |
| 特殊服务 | `[2, 4]` | 开启隐藏入口或购买高价值商品；结果必须确定，代价较高。 |
| 风险交易 | `[3, 4]` | 用较低支付换更高方差的装备或服务，风险概率在购买前公开。 |

- 经济事件本身不占用风险事件的“普通纯负面 / 高风险收益”配额；报价中的风险是交易条件的一部分，不应伪装成独立风险事件。
- 经济事件不因为深度自动提高商品品质。商品报价中的 `family` 掉落可以读取当前净化粒子档位的品质权重，但指名物品不吃掉落系数；文档必须写清是哪一种。
- 经济事件的 `E` 只记录事件额外净化粒子变化。首图第一批交易均为 `E = 0`，食品是支付，不得同时把食品价格再折算成粒子。

## 二、交易报价的统一写法

每个事件模型都按以下顺序描述，方便后续转换成数据和 UI：

1. **支付**：具体食品和数量，是否允许购买一次以上。
2. **产出**：服务目标、指名物品或掉落族；写明是否占背包。
3. **风险**：没有风险写“无额外风险”；有风险写概率、目标和叠加关系。
4. **前置条件**：合法目标、背包空位、情报标记、隐藏入口状态或本轮使用次数。
5. **结算顺序**：检查 → 扣食品 → 发放服务或物品 → 写入使用记录。

后文的“购买上限”是**每次抵达该事件的上限**。如果未来需要限制整趟远征次数，必须额外写“每次远征限用一次”，不能从“购买上限 1 次”推断出来。

## 三、经济事件模型

### 1. 垃圾桶机器人

**节点名称（地点）：** 员工餐厨废弃物处理间

**到达：** 餐厨处理间的金属桶沿着轨道缓慢移动，桶盖上的扫描眼一只接一只亮起。它把队伍的伤口、卡牌污染和背包里的可乐都列入“待处理项目”，并用旧员工语气询问：“本次服务需要标准套餐还是深度套餐？”

**模型定位：** 直接服务型医疗交易；同一次抵达只能购买一项服务。

**选择与结果叙事：**

- **标准清洁。** 你把两罐可乐放进投入口。机器人用紫外线和营养雾扫过队伍，所有存活角色得到一段均匀的恢复。
- **重点处理。** 你交出一只汉堡，让机器人把全部热量和修复剂集中到伤势最重的人身上。它不会替你处理其他人的伤口。
- **净化回收。** 你把一只炸鸡推入桶口，机器人改用过滤程序处理一名角色的污染卡牌，不提供生命治疗。

**ID：** `scrap-bin-robot`　**结构：** 3 个直接报价　**段位：** `[1, 3]`　**E：** `0`

| 报价 | 支付 | 结算效果 | 前置条件 |
| --- | --- | --- | --- |
| 标准清洁 | 可乐 ×2 | 全队存活角色回复 18% 最大 HP | 至少 1 名存活角色 |
| 重点处理 | 汉堡 ×1 | 当前生命比例最低的存活角色回复 35% 最大 HP | 至少 1 名存活角色 |
| 净化回收 | 炸鸡 ×1 | 选定一名角色，净化其 2 张污染卡牌；不回复生命 | 选定角色至少有 1 张污染卡牌 |

三项服务均无额外风险。若净化目标只有 1 张污染卡牌，则只净化现有的 1 张，不把剩余次数转成治疗或其他收益。

### 2. 量子隧穿售货机

**节点名称（地点）：** 访客大厅量子售货机

**到达：** 售货机的玻璃柜里没有固定商品，只有三块被冷光照亮的货位。它不接受所有食品，只识别可乐和炸鸡的包装条码；每次启动时，量子隧穿模块会从材料仓和装备仓各抽取一批库存，像是把别的楼层刚刚送来的货物直接挂进柜内。

**模型定位：** 高级科技商店；固定接受可乐、炸鸡，随机提供模组材料和装备。每次抵达生成 3 个货位，最多购买 2 个货位。

**选择与结果叙事：**

- **接入高级货架。** 你让售货机读取可乐和炸鸡的包装。三件随机库存会在屏幕上同时显现，物品、品质、价格和占格全部公开；确认购买后，售货机不会重新抽取结果。
- **关掉屏幕离开。** 你不交出食品，也放弃这次货架中的全部库存。

**ID：** `quantum-vending-machine`（接替现有占位 ID `vending`）　**结构：** 随机货架型商店　**段位：** `[2, 4]`　**E：** `0`

| 随机货位 | 生成范围 | 价格模板 | 占格 |
| --- | --- | --- | ---: |
| 材料货位 | 从 `servo`、`coil` 材料族中随机生成 1 件；品质在货架生成时确定 | 可乐 ×1 或 炸鸡 ×1 | 1 |
| 装备货位 | 从 `armor-plate`、`jammer`、`prybar` 装备族中随机生成 1 件；具体装备和品质公开展示 | 炸鸡 ×1 或 可乐 ×1 + 炸鸡 ×1 | 2 |
| 混合货位 | 从材料和装备的完整池中随机生成 1 件；同一货架至少保留 1 个材料货位和 1 个装备货位 | 由物品品质套用对应价格模板 | 按物品定义 |

- 三个货位在第一次打开商店时随机生成并锁定；关闭商店、重新打开节点或切换角色都不能刷新。
- 货架内容随机，但不是付款后的盲抽：具体物品、稀有度、价格、占格和风险在购买前全部可见。
- 材料和装备货位使用 `family` 生成规则，品质受当前净化粒子档位影响；不能在购买时再临时指定材料族、装备族或稀有度。
- 同一次抵达最多购买 2 个货位；购买后的货位显示为售罄，不补货、不合并、不返还食品。

### 3. 流浪回收商

**节点名称（地点）：** 西侧废料交易棚

**到达：** 一具披着旧广告布的电子生命把自己挂在折叠支架上。它只认得面包和牛奶的包装，不承认这两种食品之外还有“合法货币”；每次接通交易，它都会从废料仓和补给仓里随机翻出几件还没被压坏的东西。

**模型定位：** 基础回收商店；固定接受面包、牛奶，随机提供废料和消耗品。每次抵达生成 3 个货位，最多购买 2 个货位。

**选择与结果叙事：**

- **查看回收货架。** 你让它扫描面包和牛奶的包装。三个随机货位依次亮起，废料的具体种类和消耗品的效果都在支付前公开。
- **拒绝报价。** 你不交出食品，回收商继续寻找下一支队伍。

**ID：** `wandering-recycler`（接替现有占位 ID `wandering-trader`）　**结构：** 随机货架型商店　**段位：** `[1, 2]`　**E：** `0`

| 随机货位 | 生成范围 | 价格模板 | 占格 |
| --- | --- | --- | ---: |
| 废料货位 | 从 `scrap-piece`、`scrap-alloy`、`scrap-core` 中随机生成 1 件；具体物品和品质公开 | 面包 ×1 或 牛奶 ×1 | 1 |
| 消耗品货位 | 从营养膏、急救组件、净化安瓿中随机生成 1 件；具体物品公开 | 牛奶 ×1 或 面包 ×1 + 牛奶 ×1 | 1 |
| 混合货位 | 从废料和消耗品的完整池中随机生成 1 件；同一货架至少保留 1 个废料货位和 1 个消耗品货位 | 由物品品质套用对应价格模板 | 按物品定义 |

- 三个货位在第一次打开商店时随机生成并锁定；关闭商店或重新打开节点都不能刷新。
- 回收商只接受面包和牛奶，不接受可乐、炸鸡、披萨、废件、材料、数据存档或居民积分。
- 废料和消耗品都是实际货架库存，不会在购买后再转成其他物品；同一次抵达最多购买 2 个货位。

### 4. 未归档工单广播终端

**节点名称（地点）：** 运维公告终端室

**到达：** 终端的公告栏还在滚动播报三百年前的楼层变更。它知道某些封闭区域、遗留宝库和特殊入口的位置，却把这些信息标成“仅向完成食品配给的员工开放”。屏幕不允许队伍直接改写路线，只会在地图上留下一枚可追踪的标记。

**模型定位：** 有限情报交易；情报只揭示位置，不自动移动、不跳过节点。

**选择与结果叙事：**

- **购买楼层情报。** 你交出可乐，终端揭示一个尚未揭示的隐藏区域或隐藏宝库位置，并把标记写入本轮探索记录。
- **购买完整索引。** 你交出披萨，终端揭示一个隐藏区域和一个特殊事件节点的位置；如果当前地图没有足够的合法目标，剩余信息不会替换成其他收益。
- **离开终端。** 你不支付食品，放弃所有位置情报。

**ID：** `unarchived-workorder-terminal`　**结构：** 3 个处理选项　**段位：** `[2, 4]`　**E：** `0`

| 报价 | 支付 | 结算效果 | 前置条件 |
| --- | --- | --- | --- |
| 楼层情报 | 可乐 ×1 | 揭示 1 个合法隐藏区域或隐藏宝库位置 | 至少存在 1 个尚未揭示目标 |
| 完整索引 | 披萨 ×1 | 揭示 1 个合法隐藏区域和 1 个合法特殊事件节点位置 | 两类目标都存在 |
| 离开终端 | 无 | 不获得情报 | 放弃本次情报机会 |

- 情报标记是本轮有效的探索信息，不属于居民积分、经验、数据存档或任务物品。
- 没有合法目标时，对应报价置灰且不可支付；不能用普通节点、战斗节点或“下一条路线”填充空缺。

### 5. 特殊入口收费闸

**节点名称（地点）：** 东侧封闭访客闸

**到达：** 收费闸把队伍识别成一批迟到的访客。闸门后方确实存在一条没有出现在普通路线上的通道，但它只有在地图已经记录过该入口后才会显示完整的验证界面；没有情报标记时，终端只播报“请勿尝试猜测权限”。

**模型定位：** 极少数入口服务；只有已经被情报揭示的隐藏入口才能使用。

**选择与结果叙事：**

- **提交正式通行费。** 你交出披萨，闸门按旧员工权限完成核验，开启当前已标记的隐藏区域入口。开启不跳过当前节点，也不免除之后节点的粒子消耗。
- **伪造访客凭证。** 你只交出一只汉堡，利用闸机缓存里的旧身份尝试折价通行。入口可能打开，但错误凭证会把一张污染卡牌写入指定角色的牌组。
- **离开收费闸。** 你不支付食品，保留入口未开启状态。

**ID：** `sealed-special-airlock`　**结构：** 3 个处理选项　**段位：** `[3, 4]`　**E：** `0`

| 报价 | 支付 | 结算效果 | 风险与前置条件 |
| --- | --- | --- | --- |
| 正式通行费 | 披萨 ×1 | 开启当前已标记的隐藏区域入口 | 必须存在对应情报标记；无额外风险 |
| 伪造访客凭证 | 汉堡 ×1 | 开启当前已标记的隐藏区域入口 | 30% 概率随机污染某个角色的 1 张卡牌；风险在确认前公开 |
| 离开收费闸 | 无 | 不开启入口 | 放弃本次入口服务 |

- 入口服务只改变隐藏区域的“封锁状态”，不直接把队伍传送到隐藏区域。
- 伪造凭证的污染概率属于该报价的交易风险，不计入风险事件池，也不因为未触发污染而返还食品。
- 如果当前没有已标记且尚未开启的隐藏入口，前两个报价都不可购买。

### 6. 黑屏拍卖终端

**节点名称（地点）：** 旧董事会黑屏拍卖厅

**到达：** 黑屏挂在一间已经拆空的会议室中央，只亮着两个尚未清点的拍卖货位。终端承诺“低价获得未清点库存”，但只接受炸鸡和披萨；它会把随机生成的装备轮廓和完整风险一起显示出来，拒绝让买家在付款后才知道自己买到了什么。

**模型定位：** 风险商店；固定接受炸鸡、披萨，随机提供装备货架。每次抵达生成 2 个货位，最多购买 1 个货位。

**选择与结果叙事：**

- **查看风险货架。** 你让终端生成两个装备货位。每件装备的具体结果、价格和污染概率都在货架上显示，确认后不再重掷。
- **退出拍卖。** 你不支付食品，任由黑屏继续等待下一位买家。

**ID：** `black-screen-auction`　**结构：** 随机风险货架　**段位：** `[3, 4]`　**E：** `0`

| 随机货位 | 生成范围 | 支付 | 风险 |
| --- | --- | --- | --- |
| 低风险拍品 | 从 `armor-plate`、`jammer`、`prybar` 中随机生成 1 件装备；具体装备和品质公开 | 披萨 ×1 | 无额外风险 |
| 污染拍品 | 从完整装备池中随机生成 1 件装备；具体装备和品质公开 | 炸鸡 ×1 | 30% 概率随机污染某个角色的 1 张卡牌；概率公开 |

- 两个装备货位在第一次打开时生成并锁定；玩家可以在两个已公开货位中选择一个购买，不能购买后再重掷。
- 污染只作用于卡牌状态，不改变装备、不扣除额外食品、不直接扣 HP；风险触发与装备发放在同一笔交易中完成。
- 如果装备无法进入背包，必须在扣款前完成替换；不能因为风险货位已经生成就绕过背包容量。

### 7. 传送投递口

**节点名称（地点）：** 货运传送投递口

**到达：** 货运墙上有一排只对食品包装作出反应的投递槽。传送口不关心队伍是否能活着走完这一层，只关心被选中的物品是否已经完成封装；一旦封装完成，物品就不再属于当前背包的团灭损失。

**模型定位：** 特殊服务协同模型，不计入普通经济事件数量；每次远征最多使用一次。

**选择与结果叙事：**

- **封装并寄回。** 你支付指定食品，打开现有寄件流程，从背包中选择最多 6 个物品寄回据点。已寄送物资立即进入 `shipped`，本次远征团灭时仍保留。
- **不使用投递口。** 你不支付食品，所有物品继续留在当前背包中。

**ID：** `dispatch-chute`　**结构：** 2 个处理选项　**段位：** `[1, 4]`　**E：** `0`

| 报价 | 支付 | 结算效果 | 限制 |
| --- | --- | --- | --- |
| 封装并寄回 | 披萨 ×1 | 开启寄件流程；最多寄回 6 个背包物品，寄件成功后进入 `shipped` | 每次远征限用 1 次；食品、居民积分和临时战斗效果不可寄送 |
| 不使用投递口 | 无 | 不改变背包和 `shipped` | 放弃本次投递机会 |

- “6 个物品”按物品实例计数；一件占 2 格的装备仍算 1 个物品，不按 2 格拆分。当前物品定义 `maxStack` 均为 1，因此不产生堆内拆分问题。
- 只在玩家确认具体寄件清单后扣除食品；打开寄件界面、勾选物品或取消寄件都不扣费。
- 本文采用全局《临期食品设计》的食品支付口径：投递口只收披萨 ×1，不再叠加“寄件时扣 5 粒子”。现有 `explore/session.ts` 与数据注释中的 `-5` 属于旧实现口径，正式接入时应移除或改为食品支付，并同步探索规则、数据和 UI。

## 四、事件池检查表

| 检查项 | 结果 |
| --- | --- |
| 普通经济模型 | 6 个：医疗、高级科技商店、基础回收商店、情报、特殊入口和风险商店 |
| 特殊协同模型 | 1 个：传送投递口；保留经济文档中的交易规则，但类别仍按特殊事件处理 |
| 统一类别 | 普通模型使用 `category: economy`、`kind: merchant` |
| 支付资源 | 全部为明确食品和数量；不使用居民积分、模糊食品余额或物品价值折算 |
| 交易次数 | 固定服务每次抵达完成 1 项；基础/高级商店每次最多购买 2 个货位；风险商店最多购买 1 个货位；投递口每次远征最多 1 次 |
| 商店随机性 | 商店货币组和商品类别固定；货架物品在首次打开时随机生成，展示后锁定，不刷新 |
| 结果类型 | 治疗、卡牌污染净化、消耗品、材料、装备、有限情报和特殊入口服务 |
| 背包口径 | 消耗品与材料 1 格，装备 2 格；交易前必须通过容量和替换流程 |
| 风险口径 | 只在报价中公开概率；污染目标、数量和是否叠加均写明，不占风险事件配额 |
| 路由边界 | 情报只揭示位置；入口服务只解锁隐藏入口，不跳过节点、不免粒子、不重排路线 |
| 排除内容 | 居民积分、长期成长、卡牌抽取、维修/重铸、普通路线便利、剧情任务和食品互换 |

### 2. 建议的效果契约

当前 `ExploreEffect` 主要描述直接治疗、掉落、能量和投递口开启，尚没有交易支付、情报和入口状态的表达。接入经济事件时建议新增明确的声明式效果，而不是把支付塞进 `description` 或复用 `GAIN_LOOT`：

- `PAY_FOOD`：具体 `itemId` 与数量；只在交易原子结算阶段执行。
- `MERCHANT_STOCK`：商店固定接受的食品、商品类别、货位数量、购买上限、随机种子和已生成库存；UI 读同一份库存生成货架。
- `MERCHANT_TRANSACTION`：货位 ID、支付清单和售出状态；防止同一货位重复购买或关闭商店后刷新。
- `CLEAN_CORRUPTION`：目标角色选择方式和最多净化张数。
- `REVEAL_NOTE`：情报类别、目标 ID 和本轮有效期；不直接修改路线。
- `OPEN_HIDDEN_AREA`：已标记入口 ID；只改变封锁状态。
- `APPLY_TRADE_RISK`：概率、风险类型、目标和数量；风险必须在报价确认前可见。

这些效果应由探索会话统一处理，并保证“检查前置条件 → 扣食品 → 执行结果 → 写交易记录”的顺序。物品增加仍走现有 `addItems`，背包满仍走 `pendingPickup`，不要为经济事件另写一套容器逻辑。

### 3. 分阶段接入建议

1. **第一阶段：** 先接入垃圾桶机器人、量子隧穿售货机和流浪回收商。它们只需要食品支付、已有消耗品/材料/装备掉落和背包原子结算。
2. **第二阶段：** 接入黑屏拍卖，补齐随机库存生成、公开风险和装备 2 格替换流程。
3. **第三阶段：** 接入情报终端和特殊入口收费闸，先确定隐藏区域、情报记录和入口状态的数据结构，再开放事件抽取。
4. **投递口：** 在食品支付与旧版 `-5` 粒子扣除之间完成全局统一后再解除现有占位状态。

在对应效果和 UI 未接入前，事件保持 `disabled: true`。不能只把 `disabled` 改成 `false`，再用空 `effects` 或一段描述文字假装完成交易。

## 六、与其他事件池的分工

| 事件池 | 负责内容 | 经济事件不重复承担的内容 |
| --- | --- | --- |
| 生存 | 无支付的治疗、净化、医疗物资取舍 | 不把免费治疗伪装成食品交易，也不替换生存事件的稳定恢复主职能 |
| 成长 | 材料、装备、经验和卡牌机会的搜寻 | 不用经济事件直接发经验、卡牌或免费成长物 |
| 风险 | 纯负面和高风险收益事件 | 不把交易失败写成未公开的随机惩罚，不占用风险事件配额 |
| 路由 / 能量 | 普通路线便利、粒子增减、区域推进服务 | 不用食品免除普通节点粒子、不跳段、不重排路线 |
| 特殊 | 任务、终局、投递和其他不适合常规类别的服务 | 投递口保留在特殊类别，不把寄回据点写成普通商品 |

经济事件的核心决策分成两种：固定服务中，玩家判断当前食品和队伍状态是否值得换取确定结果；随机商店中，玩家判断公开货架上的随机物品是否值得用该商店限定的食品支付。只要支付类型、货架结果、空间、购买上限或风险有一项含糊，模型就不应进入可抽取事件池。
