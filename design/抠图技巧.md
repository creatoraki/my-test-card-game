# 立绘抠图技巧

AI 生成的敌人立绘通常带一层纯色底（多为洋红紫）。项目约定素材本身就是透明 PNG（见 `src/ui/enemyArt.ts` 顶部注释），
抠图是**离线一次性产物，运行时不参与**。工具是 `scripts/chroma-cut.mjs`，零依赖（PNG 解码/编码全靠 Node 内置 zlib），
新素材直接复用，不要另写脚本。

## 快速上手

```bash
node scripts/chroma-cut.mjs "src/assets/敌人立绘/<角色>/idle.png" "src/assets/敌人立绘/<角色>/idle-cut.png"
```

约定：源图 `idle.png` 保留不动，产物叫 `idle-cut.png`（沿用废品机器人的命名）。

先跑默认参数看结果，不合适再按下面的「调参思路」调。

## 脚本在做什么

理解这四步，调参才不是撞运气。

1. **定背景基准色**：取四角均值（纯色底的四角必是背景），换算出基准色相 `refHue`。
2. **从画布四边 flood fill**：只抠**与画布边缘连通**的背景。
   这是关键设计——不能对全图直接套颜色判据，角色身上难免有同色系像素（废品机器人胸口就有粉紫霓虹图标），
   全图阈值会把它一起抠掉，只有连通性能把它和真背景分开。
3. **补背景孔洞**：被角色围住的背景（手臂与身体之间、电线缝隙）与画布边缘不连通，上一步够不着。
   这里同样只认背景色相，外加一道**面积闸 `min-hole`**——假设是「角色身上的同色系细节都是零散小块」。
4. **内收 1px + 软边羽化**：吃掉抗锯齿留下的背景色描边，并对边缘半透明像素做去色污染
   （反解前景色，否则边缘残留背景色调）。羽化严格限制在边缘那一圈，角色内部一律原样不透明。

**背景判据走色相 + 饱和度，不是 RGB 距离。** 因为角色投在背景上的阴影色相仍是背景色相、只是明度掉一半，
RGB 距离会把它当前景留下一片紫块；反过来角色身上被紫光染到的金属反光 RGB 距离虽近，但饱和度很低，靠 `min-sat` 就能摘干净。

## 参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--hue-tol` | 14 | 背景色相容差（度）。背景与角色靠色相分家，**这是主判据**。 |
| `--min-sat` | 0.5 | 背景最低饱和度（0-1）。角色身上被背景光染到的反光饱和度低，靠这道闸摘掉；调低会开始啃角色。 |
| `--min-hole` | 300 | 背景孔洞连通块的最小面积。小于此的同色系碎片视作角色细节保留。 |
| `--threshold` | 60 | 软边羽化的颜色容差。只影响边缘 1px 的 alpha 过渡与去色污染，一般不用动。 |

## 调参思路

跑完先读 stdout 自检：背景色/色相、孔洞补掉的像素数、裁剪框、产物尺寸。
**若裁剪框接近整幅原图尺寸，说明有背景没抠干净**（可能是背景本身带渐变），先看这一条。

然后直接打开产物 PNG 核对两件事：背景是否全透明、边缘有无背景色描边残留；角色身上的同色系细节有没有被误抠出洞。

两类典型故障的对策：

- **背景有残留紫块** → 调高 `--hue-tol`，或调低 `--min-sat`，或调低 `--min-hole`（残留是碎块时用这个）。
- **角色被啃出洞** → 调低 `--hue-tol`，或调高 `--min-sat`。

**两者冲突时，优先保住角色**——宁可留一点背景，再单独收窄。

注意 `min-hole` 和 `hue-tol` 是互相拉扯的：`min-hole` 是「靠面积保住角色细节」的兜底，一旦放开它，
角色上所有同色系细节就只剩 `hue-tol` 这一道保护。所以放开 `min-hole` 前，先确认要保的细节色相离背景足够远。

## 案例：收音机机器人（2026-07-16）

源图 1024×1024，背景实测 `rgb(194, 78, 191)`、色相 302°。最终命令：

```bash
node scripts/chroma-cut.mjs "src/assets/敌人立绘/收音机机器人/idle.png" \
  "src/assets/敌人立绘/收音机机器人/idle-cut.png" --min-hole 1 --hue-tol 9
```

默认参数不够用，过程是这样的：

1. **默认参数**（`--min-hole 300 --hue-tol 14`）：把手右侧和腿间电线之间残留紫块。
   原因是那些背景碎块被角色的电线切得很小，面积不到 300px 的闸门，被当成角色细节保留了。
2. **`--min-hole 1`**：紫块清干净，但顶部调谐刻度带的粉色霓虹被啃出黑色缺口。
   那片粉偏品红，色相正好落在背景 302° 的 ±14° 容差内，失去面积闸保护就被当背景抠掉了。
3. **`--min-hole 1 --hue-tol 9`**：判据只认 293–311°。残留紫块本身就是 302° 的背景色，照抠不误；
   刻度和腿部的粉色霓虹在 320° 开外，安全。最终产物 719×767。

**可复用的经验**：当背景碎块被角色细节切得很碎（电线、栏杆、镂空结构），面积闸会失效——
它分不清「小块背景」和「小块角色」。这时把 `min-hole` 放开到 1、改用收窄 `hue-tol` 来保护角色，
前提是要保的霓虹/高饱和细节色相离背景有 10° 以上的差。
