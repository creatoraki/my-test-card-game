## 六、设计方案

### 1. 分层架构（关注点分离）

```
data （内容：卡/角色/敌人/遭遇战/探索卡/地图）
  │  声明式描述符
  ▼
engine （纯 TS 战斗规则）      explore （纯 TS 探索牌局规则）
  │  engine/index.ts            │  explore/session.ts
  │                             │  ↘ 动态难度 → EncounterModifier ↘
  ▼                             ▼                                ▼
store （Zustand：克隆式不可变更新；runStore 编排两者的往返）
  │  订阅 / 派发
  ▼
ui （React：纯展示 + 交互，不含规则）
```

`engine/` 与 `explore/` 是两个互不 import 的纯逻辑层（只有 `explore/session.ts` 单向读 `engine` 的 rng 与 `EncounterModifier` 类型）。战斗引擎不认识探索难度，只认识 `EncounterModifier` 这组改造；日后任何动态难度来源都能复用同一个接口。

- **引擎与 React 解耦**：所有战斗规则在 `engine/` 内以纯函数实现，直接修改传入的 `BattleState`；由 store 层负责 `structuredClone` 后再调用，从而对 React 呈现不可变更新。引擎因此可被单测、可复现、可存档（`BattleState` 无函数）。
- **可复现随机**：随机种子 `rngState` 保存在 `BattleState` 内，配合 mulberry32，相同种子得到相同战斗过程，利于测试与回放。

### 2. 数据驱动 + 声明式效果

- 卡牌和敌人招式都用同一套 `EffectDescriptor`（`{ type, amount, target, status, stacks… }`）声明效果，由 `effects.ts` 统一解释执行。
- 新增一个机制通常是新增一个 `EffectType`，再在 `applyEffect` 的 `switch` 中增加分支；新增内容（卡、敌人、遭遇战）只改 `data/`，无需改引擎。

### 3. 状态系统用“行为钩子”

- 状态定义（`statuses.ts`）携带 `onRoundStart` / `onRoundEnd` / `onTick` / `modifyOutgoingDamage` / `modifyIncomingDamage` / `onAfterAttacked` 等钩子。
- 伤害在 `ops.ts` 中走一条结算管线：施放者修正（力量/虚弱）→ 目标修正（易伤）→ 命中 → 暴击 → 防御减伤 → 格挡 → 护盾吸收 → 落定 → 反伤（荆棘）。顺序是硬规定，固定伤害只跳过防御与格挡两段。
- 为打破循环依赖，`statuses.ts` 只 import 类型与规则，通过 `ctx.ops`（`EngineOps` 原语集合）反向调用引擎实现，而不是直接 import `ops.ts`。

### 4. 时刻制（tick）——核心差异化机制

- 全局时刻时钟与敌人行动排程集中在 `scheduler.ts`：出普通牌 `advanceTick(1)`，出速攻牌不推进；每推进 1 时刻就结算所有到点敌人。
- 敌人 `castTick` 是技能基础延迟，实际行动时刻还要叠先手差：`T = max(1, castTick + 我方先手均值 − 敌方先手)`（`stats.enemyActDelay`）。我方先手越高，敌人越晚动手；有人阵亡导致均值变化时节奏会跟着变。
- 该模块被刻意隔离，日后要换成纯先攻轴等其他调度，只需替换这一处。

### 5. 集中可配置的规则

- `rules.ts` 汇总所有平衡旋钮：资源经济、小队手牌修正、时刻推进、虚弱/易伤系数、结算口径、负重、升级倍率、养成段 `progression` 与卡组锻造段 `deck`。调平衡主要改这里。
- `deck` 段与部分面板数字是《角色养成设计.md》第八章待确认数值的草案，定稿后直接调整规则数字。

### 6. 角色养成：固定面板 + 卡组锻造

- **无等级、无属性点**：角色的 16 项面板写在 `characters.ts` 的 `base: StatBlock` 中，进游戏后不再变化。`grantExp` 只把经验放进 `CharacterState.exp` 池子，没有升级和加点；长期成长来自装备与卡组构筑。
- **属性分三层结算**：局外两层（角色基础 + 装备）在 `townStore.deriveStats` 合并成完整面板传给 `createBattle`；战斗内那层（卡牌 `APPLY_STAT_MOD`、状态、场景）写进 `Combatant.mods`，由 `engine/stats.statOf` 读取时叠加并对概率类封顶。引擎里任何属性读取都必须走 `statOf`，不要直接读 `cmb.stats`。
- **伤害按倍率而非固定点数**：卡牌与敌人招式共用同一口径，`multiplier` 乘施放者攻击力，`amount` 表示固定伤害。这样战斗卡实例与城镇个人卡组数值一致，卡牌强化与敌我双方不需要两套规则。
- **经验的唯一去处是卡组锻造**：升卡组等级（只改抽卡稀有度权重，不强化已有卡）、抽卡、删卡、降低最小卡组下限。抽卡先按等级摇稀有度，再从角色对应稀有度的专属池生成 3 张候选，允许重复，三选一；候选存在 `pendingDraw` 并随档案持久化，经验消耗后必须选完。
- **稀有度限携是硬约束**：普通 20、罕见 6、稀有 3，不能被卡组等级、装备或模组提高，确保高稀有度卡是有限选择而非可堆叠资源。
- **战斗卡组 = 上阵角色个人卡组的集合**：`launchBattle` 把 `party` 中每人的 `deck` 做 `structuredClone` 后 flat 合并，个人卡组归属清晰（`ownerCharId` 决定配色、禁用和加成），战斗改动不污染城镇资产。

### 7. 探索牌局：整个游戏只有一种交互语言

> 本节保留的是历史设计记录。当前探索代码已采用失真路由图与战斗签流程；区域危险度与残片均已废弃，以 `design/探索模式设计.md` 和 `docs/code-map/explore.md` 为准。

远征层刻意不做另一套独立的地图操作语言，而是通过路由图节点、战斗签和统一的卡牌表达探索决策。玩家在节点选择、路线入口和战斗签之间推进远征；压力来自粒子档位、血量继承、战斗难度和背包取舍。

几条仍然有效的设计决定：

- **血量跨战斗继承是地基**：没有它，休整、下一场战斗的取舍和撤退都失去意义，落点是 `AllyInit.startHp` 与 `resolveBattle` 的回填。
- **探索产出是实物**：战斗掉落先进入背包，居民积分通过城镇回收和远征结算产生；团灭清算会丢失未寄回的背包物品。
- **投递口是风险管理工具**：寄回的 `shipped` 不受团灭影响，结算页优先展示它，玩家可以用消耗换取确定性。
- **轨迹是远征历史**：已完成的节点/卡牌沿轨迹保留，结算页复用同一组件做回顾。

### 8. 物品层为什么是第三个纯 TS 层

`src/items/` 与 `engine/`、`explore/` 平行，而不是塞进其中任何一个。理由是对称消费：

- **探索层**需要它做背包与掉落（`ExploreState.backpack`、战斗结算的 `rollDropTable`）。
- **城镇层**需要它做仓库与穿戴（`townStore.storage`、`equipModsOf`）。

放进 `engine/` 会让战斗引擎认识背包；放进 `explore/` 会让 `townStore` 为了取得 `ItemStack` 类型而反向依赖远征层，破坏“城镇不认识远征”的边界。

依赖图：

```
items/  ──（仅 type-import）──▶  engine/types.ts（StatBlock）、engine/rng.ts
explore/session.ts ──▶ items/*        townStore ──▶ items/*        data/items.ts ──▶ items/types
```

`items/` 不 import `explore/` 与 `store/`。消耗品使用 `items/types.ts` 自己的 `ItemUse`，而不是直接复用 `explore/types.ts` 的 `ExploreEffect`；翻译只在 `explore/session` 一处完成。

引擎不认识背包与占格，只认识 `BattleState.burdenPenalty` 这个开战瞬间快照。换算本身只有 `engine/stats.burdenPenalty` 一处，探索页读数与开战快照共用它。

### 9. 可扩展点（后续方向）

- **内容替换**：`data/` 主要放占位默认内容，替换正式卡牌、角色、敌人、遭遇战和地图即可。
- **据点设施**：开放设施时修改 `TownScreen` 的设施登记和 `facilityScenes.ts`；给设施填内容时新增 `ui/<Xxx>Scene.tsx` 并在 `FACILITY_CONTENT` 登记，不新增 `Screen` 成员。持久资产统一放 `townStore`。
- **新探索卡**：在 `data/exploreEvents.ts` 增加定义并登记到对应事件池；需要新效果时同步 `explore/types.ts` 和 `explore/session.ts`。
- **动态难度**：任何改造一场遭遇战的需求都走 `EncounterModifier`，包括追加敌人、全体开局状态、`castTick` 调整和 HP 倍率。
- **新机制**：增加 `EffectType` 与 handler，或增加 `StatusDef`、敌人招式和意图脚本。
- **过场演出**：新增过场特效时修改 `transitions.ts` 的 `FX` 与对应 CSS 关键帧；修改跳转演出时调整 `ROUTE_FX`。
- **系统级扩展**：资源可扩成每角色独立池、结转和上限；调度可替换轴制；`BattleState` 可序列化，便于接入存档与回放。
