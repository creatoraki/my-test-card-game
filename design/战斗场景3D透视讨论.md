# 战斗场景 2D 立体感与透视运镜设计讨论

## 1. 讨论结论

本项目的战斗画面虽然使用 React、CSS 3D 和透视变换实现运镜，但美术本质上是 2D 赛璐璐立绘与 2D 房间背景。目标不是把整张画面硬转成真实 3D，而是利用 2D 画面已有的透视构图，建立稳定、可读、具有纵深感的战斗舞台。

核心结论：

> **背景负责建立空间，敌人负责建立深度，二维推镜负责叙事，前景遮挡和分层视差负责强化立体感，HUD 负责保持稳定可读。**

因此，后续不应继续单纯增加 `rotateY`、`rotateX`、平移和弧线补偿的幅度。更重要的是让所有运动都服从背景已有的消失点与地面透视关系。

## 2. 当前背景的空间特征

当前使用的“霓虹城市”战斗背景本身已经是一张完整的室内空间构图，包含以下透视证据：

- 左右墙面向房间深处的窗户区域收拢。
- 地面占据画面下方的大面积区域，形成明显的纵深通道。
- 窗户和房间深处是视觉上的主要消失方向。
- 地面明暗、墙体结构和灯光已经提供了前景、中景、远景的空间层次。

这意味着背景不是普通的平面色块，而是一张已经完成透视绘制的二维舞台。背景中的墙体、地面、灯带和窗户已经拥有自己的透视关系，不能在镜头运动时被当成独立的 3D 平面随意拉开。

### 2.1 背景运镜的约束

背景图中的房间地面和墙面处在同一张图片里。若只给背景层施加明显的独立深度视差，容易出现以下问题：

- 敌人脚底与地面接触点滑开。
- 地面反光和墙体透视线与角色运动不同步。
- 镜头推近后房间像一张被拉伸的贴图，而不像镜头进入房间。
- 原本统一的消失点被不同层的位移破坏。

因此，背景图片、敌人主体和脚下接触关系应视为一个主舞台整体，主运镜以二维的 `translate + scale` 为主。明显的视差应交给额外添加的雾、碎片、光尘、线缆或前景遮挡层。

## 3. 2D 画面表现强立体感的方法

### 3.1 固定消失点

所有新增的空间线索都应尽量指向背景已有的消失方向。可以使用：

- 向窗户深处收拢的地面线。
- 越远越密集的地面横向分段线。
- 向消失点汇聚的墙面灯带、管道和框架。
- 与角色脚底对应的地面接触线。

不建议新增与背景透视方向冲突的斜线，也不建议单独旋转整张背景来制造“立体感”。2D 画面中的立体感首先来自透视线、遮挡关系、尺寸变化和接地点，而不是来自画布本身的倾斜。

### 3.2 前中后景分层

建议将场景表现拆成以下层次：

```text
背景房间：墙体、窗户、地面、固定灯光
远景氛围：远处雾、尘埃、弱灯光
主舞台：敌人立绘、脚下阴影、血条与意图
近景氛围：雨丝、扫描线、光尘、碎片
前景遮挡：靠近镜头的线缆、墙体边缘、雾带、设备残片
HUD：顶部信息条、队伍 UI、手牌、卡牌说明面板
```

各层的视差应克制地递增：

```text
背景房间：0 或与主舞台保持锁定
远景氛围：0.7 ~ 0.9
主舞台：1.0
近景氛围：1.1 ~ 1.25
前景遮挡：1.2 ~ 1.5
HUD 装饰：0.03 ~ 0.10
交互文字与按钮：0
```

这里的数值表达的是相对运动幅度，不要求直接对应 CSS `translateZ`。重点是背景与角色的接触关系稳定，前景元素的运动速度明显高于远景。

### 3.3 遮挡关系

遮挡是 2D 画面制造纵深最有效的手段之一。可以让：

- 近景雾、碎片或线缆从角色前方掠过。
- 前景装置只露出画面边缘的一角。
- 角色脚边被地面结构轻微遮挡。
- 攻击特效短暂盖住目标轮廓的一部分。
- 近景粒子经过角色前方时速度更快、透明度更高。

遮挡层必须使用 `pointer-events: none`，不能阻挡敌人、卡牌和 HUD 的交互。

## 4. 敌人的空间站位

敌人不应只作为一排横向排列的立绘。即使仍然使用横向槽位，也应让每个槽位表现出房间地面上的不同深度。

建议每个敌人拥有以下表现参数：

```ts
interface EnemyPlacement {
	dx?: number;
	dy?: number;
	scale?: number;
	depth?: number;
	groundY?: number;
}
```

其中：

- `dx` / `dy`：相对基础槽位的位置修正。
- `scale`：敌人距离镜头的视觉尺寸。
- `depth`：用于决定层序、视差速度或前后遮挡关系。
- `groundY`：敌人脚底与地面透视位置的对应点。

设计规则：

- 越靠近房间深处，敌人越小、脚底越接近地平线或窗户方向。
- 越靠近画面前方，敌人越大、脚底越靠近画面下方。
- 敌人的脚底必须稳定接触地面，不能只放大立绘而不调整落点。
- 体型缩放应以脚底为缩放原点，当前 `CombatantView` 的 `transform-origin: 50% 100%` 方向是正确的。
- 大型敌人不仅要更大，也应有更宽的脚下阴影和更靠前的空间位置。
- 前后敌人的层序应能形成轻微遮挡，而不是所有敌人永远互不重叠。

可以采用三档深度作为初始设计：

```text
远景：scale 约 0.82 ~ 0.92，groundY 较高
中景：scale 约 0.95 ~ 1.05，作为默认战斗区域
近景：scale 约 1.08 ~ 1.18，groundY 较低
```

具体数值应按敌人立绘实际尺寸和背景地面位置调整，不要为了统一数值而牺牲脚底接触关系。

## 5. 瞄准运镜的优化方向

当前瞄准态在敌人悬停时同时驱动：

- 固定推近 `scale`。
- 横向偏航 `yaw`。
- 纵向俯仰 `pitch`。
- 横向平移 `pan`。
- 纵向平移 `panY`。
- 弧线抬升 `arc`。

这些运动同时作用于整个 `.battle-scene`，容易产生“画面歪斜、目标滑动、鼠标和镜头互相抢控制权”的感觉。尤其是目标移动后，敌人可能从鼠标指针下方滑开，削弱了卡牌目标选择的可靠性。

### 5.1 推荐的交互流程

推荐把“瞄准反馈”和“攻击分镜”拆开：

```text
选中指向敌人的卡牌
	-> 场景只做轻微整体推近
	-> 鼠标悬停敌人时只改变目标反馈
	-> 敌人高亮、准星、脚下锁定圈或其他目标提示
	-> 点击敌人确认目标
	-> 使用二维 translate + scale 进行攻击分镜
	-> 命中特效、飘字、震屏和前景冲击
```

悬停时不建议让整个场景持续追随鼠标。目标反馈可以包括：

- 敌人轮廓或轮廓外发光。
- 目标脚下的锁定圈或光带。
- 目标周围的准星、扫描框或角标。
- 非目标敌人轻微降亮。
- 鼠标指针或卡牌目标状态发生变化。

### 5.2 如果保留悬停运镜

如果仍希望保留轻微的悬停镜头，应只保留一个主要动作，不要让旋转、平移和弧线全部叠加。可以从以下克制范围开始：

```text
scale：1.05 ~ 1.10
yaw：0 ~ 2deg
pitch：0 ~ 1deg
panMax：16 ~ 28px
panMaxY：8 ~ 16px
arc：0 ~ 4px
进入瞄准：220 ~ 280ms
目标切换：160 ~ 220ms
退出瞄准：180 ~ 240ms
```

其中更推荐只保留 `scale` 加极小的 `pan`，或者只保留 `scale` 加极小的 `yaw`。常驻瞄准态是玩家读牌和点选目标的状态，镜头幅度必须小于攻击分镜。

### 5.3 分镜运镜

点击目标后的攻击分镜可以继续使用现有的 `computeCamera`，因为它的职责是把目标清晰地呈现在画面中，而不是辅助鼠标选择。

分镜建议保持以下原则：

- 以 `translate + scale` 为主。
- `yaw / pitch` 默认保持 0。
- 目标不必永远精确贴到屏幕中心，可以保留房间消失点和地面透视。
- 若需要偏置，最终焦点可以使用“目标焦点与房间消失点的混合”，例如目标权重 0.65、消失点权重 0.35。
- 命中时使用顿帧、震屏、局部冲击和前景特效强化攻击感，而不是继续增加镜头旋转。

## 6. 相机与背景测量的技术约束

当前相机计算使用 `getBoundingClientRect()` 和 `screenToWorld()` 将屏幕矩形反投影到设计坐标。这个方法在纯缩放和平移下比较稳定，但场景带有 `rotateY` / `rotateX` 后，矩形已经是透视投影后的包围盒，中心会产生系统性偏差。

因此：

- `computeCamera` 的测量应尽量安排在姿态已经归零的阶段。
- 常驻瞄准态不应依赖带旋转的精确反投影来确定目标位置。
- 后续如果需要更稳定的目标焦点，可以为敌人登记独立的视觉焦点，而不是始终使用整个立绘包围盒中心。

例如，焦点可以是角色脸部、胸口、武器或攻击接触点：

```ts
interface EnemyVisualFocus {
	x: number; // 立绘局部坐标比例
	y: number;
}
```

这类焦点属于表现层数据，不进入战斗引擎状态，也不影响战斗规则和存档。

## 7. UI、角色 UI、卡牌 UI 和顶部信息条的深度分层

当前顶部信息条、底部队伍栏、手牌和卡牌说明面板位于 `.battle-scene` 外部。这是正确的基础结构，不应让所有 UI 直接跟随 3D 相机旋转或缩放，否则会造成文字变形、操作区域漂移和界面参照不稳定。

推荐将 UI 分成三类：

### 7.1 世界 UI

世界 UI 绑定在角色或战场上，可以参与主运镜，但要控制缩放：

- 敌人血条。
- 敌人意图。
- 状态和护盾徽章。
- 伤害数字和治疗数字。
- 角色脚下阴影与锁定圈。
- 命中特效。

表现原则是“跟随角色位置，但不必完全跟随角色尺寸”。例如血条可以随角色平移，但通过反向缩放保持文字和数字的可读尺寸。

### 7.2 前景控制台 UI

底部队伍栏和手牌不应跟随战场相机大幅移动，但可以通过自身的层次感参与空间构图：

- 手牌托盘作为画面最近景。
- 卡牌之间存在轻微的前后错位。
- 悬停卡向前浮出，其他卡略微压暗。
- 托盘边缘增加玻璃反射、阴影或前景遮挡。
- 战场推镜时，托盘装饰层可以做很小的反向漂移。
- 实际卡牌点击区域保持稳定，不能为了视差改变交互定位。

手牌的视差应很小，推荐使用 `0.03 ~ 0.10` 的相对运动幅度。它的作用是让玩家感觉自己位于战场前方的操作台后，而不是让手牌真的被镜头推走。

### 7.3 固定屏幕 UI

以下内容应保持屏幕空间固定：

- 顶部信息条的文字和按钮。
- 法力水晶。
- 时刻标尺。
- 结束回合按钮。
- 卡牌说明面板的正文。
- 胜负遮罩和确认按钮。

顶部信息条可以让装饰参与极小的视差，但交互内容必须固定：

```text
文字与按钮：0
玻璃边框：0.02 ~ 0.04
扫描线与反光：0.05 ~ 0.10
阴影：按镜头状态变化
```

建议增加独立的、不可交互的装饰层，而不是让整个顶部信息条进入 `.battle-scene`。

## 8. 推荐的 DOM 与样式分层

后续如果实现 UI 视差，可保持现有场景和 HUD 的职责边界，并补充一个装饰层：

```text
battle
├─ battle-scene
│  ├─ background
│  ├─ ambience
│  ├─ enemies
│  └─ foreground fx
├─ ui-depth-decorations
│  ├─ topbar decorative layer
│  └─ hand tray decorative layer
├─ fixed hud
│  ├─ topbar interactive content
│  ├─ ally bar
│  ├─ hand cards
│  └─ card info panel
└─ overlays
```

实现约束：

- `battle-scene` 使用完整场景相机。
- `ui-depth-decorations` 使用极小的二维位移或反光运动。
- `fixed hud` 不旋转、不缩放，保持可读和可点击。
- 装饰层统一使用 `pointer-events: none`。
- 不把可交互按钮包进带 `transform` 的装饰层。
- 不给包含多个 3D 深度层的祖先增加会触发 flatten 的 `filter`、`opacity`、`overflow` 或不必要的 `transform`。

## 9. 实施顺序建议

建议按以下顺序迭代，每一步都能单独观察效果：

1. 先校准敌人的脚底、阴影、`scale` 和背景地面接触关系。
2. 将敌人从简单横排调整为远、中、近三档空间站位。
3. 降低或关闭瞄准态的 `yaw`、`pitch`、`panY` 和 `arc`，先验证目标选择是否稳定。
4. 将悬停目标反馈改为高亮、准星、脚下锁定圈等局部反馈。
5. 保留点击后的二维推镜作为攻击分镜，确认目标后再放大和居中。
6. 添加不影响交互的近景雾、碎片、线缆和光尘，建立前景视差。
7. 最后为手牌托盘和顶部信息条增加极小的装饰视差。

不要同时修改背景透视、敌人站位、瞄准相机和 HUD 层级。否则难以判断立体感变化来自哪一层，也容易把背景已有的透视关系破坏掉。

## 10. 最终设计原则

- 2D 立体感首先来自消失点、地面接触、尺寸变化、遮挡和分层运动。
- 背景已经有房间透视时，不要用大幅 `rotateY` / `rotateX` 强行追加另一套透视。
- 背景与敌人的脚底关系优先于强烈视差。
- 悬停选择目标时，镜头不能把目标从鼠标下方拖走。
- 选目标负责可读反馈，点击确认后才负责电影化对焦。
- 角色世界 UI 可以跟随角色位置，但文字和按钮要抵消过度缩放。
- 手牌和顶部信息条可以通过装饰层参与空间感，交互内容保持固定。
- 视差是空间辅助，不应压过卡牌信息、敌人状态和操作反馈。
